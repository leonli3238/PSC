## 二、逐页讲稿

### P1 封面（8 秒）

各位老师好，我是[姓名]，导师是[导师]。我汇报的题目是《LLM 多智能体边本地差分隐私子结构计数的执行可信性》。

### P2 目录（7 秒）

汇报分六部分。重点在第二部分"现状与缺口"，因为本课题的立足点，就是几条成熟研究线交叉处的空白。

### P3 背景（32 秒）

先说背景。用自然语言让大模型直接分析图数据越来越普遍，子结构计数是常见任务，但它**既不准也不安全**。

Nguyen 和 Yan 2024 的测量显示：20 到 30 个节点的图上，LLM 数三角形的准确率只有 **7.21%**。

同时，图的每条边都编码一段个体关系——通信记录、交易往来、医患接触，直接写进 prompt 就是泄露。社交网络、金融风控、公共卫生，这两个需求同时存在。

### P4 ε-edge LDP 与 PSC（35 秒）

PSC 是目前唯一同时处理这两件事的框架。它有三类角色：

隐私控制器把 ε 拆成 ε1、ε2、ε3，用**代码**执行随机响应、带噪最大度与图投影、Laplace 机制；

curator 设计分布式计数算法并聚合；

n 个节点智能体各自只持有自己的邻居表，由 **LLM** 按规则算出本地计数 c_i，再加噪上报。

一句话：DP 机制由代码做，本地计数由 LLM 做。

### P5 问题的提出（42 秒，关键页）

这一页是全场的转折。

ε-edge LDP 的承诺要成立，需要三个条件：第一，只有扰动边、带噪度数、加噪计数离开节点；第二，每个量只发布一次；第三，被加噪的量必须由**相邻输入上灵敏度不超过 GS 的确定性规则 f** 产生。

前两条由代码保证，第三条没有保证——因为 c_i 是 LLM 算的。

GS 是对规则函数推出的上界：degree 是 1，3-star 是 C(D−1, 2)，triangle 是 d̂max − 1。但真正被加噪的是 LLM 的输出 L(x)。DP 要求相邻输入上 |L(x) − L(x′)| ≤ GS，而 LLM 没有这个性质。

所以问题不是"LLM 会算错"，而是"**被加噪的数不是规则函数算出来的**"。

### P6 现状一：LLM 图推理（15 秒）

第一条现状是 LLM 图推理。NLGraph、GraphWiz、GraphArena 把图任务拆到节点级，提升了规模和准确率；但子结构计数仍是薄弱环节，而且这一支只优化准确率，完全没有考虑隐私。

### P7 现状二：edge LDP 图统计（15 秒）

第二条是 edge LDP 图统计。随机响应、k-star、三角形、k-core、truss，机制都很成熟。它们的共同前提是：本地计算由确定性代码完成，灵敏度可以直接对那段代码推导。

### P8 现状三：DP 审计与验证（15 秒）

第三条是 DP 审计与程序验证。黑盒检测、机器学习审计、Fuzz、LightDP、Duet 都已成熟；但它们审计的对象是训练算法或人写的程序，相邻输入由检验者按代码语义构造。

### P9 研究路线对照（26 秒）

把三条线排到同一根轴上：本地计算的执行者是谁、LLM 出错时保证还成不成立。

四条成熟研究线各自成立，唯独 PSC 所在的这一行，保证建立在"L 等于 f"这个假设上，既没有审计，也没有绑定。这就是空白领域。

### P10 三类缺口（26 秒）

缺口有三类：

理论上，已有定理都假设 f 是确定性函数；执行者变成随机黑箱、输出还与私有输入相关时，这个前提直接失效。

方法上，灵敏度靠人工编写的任务模板表，新增任务要人工补条目，也没有消息校验。

评估上只有相对误差，既不给实际 ε 的下界，也不检验执行者是否偏离规则——误差小不等于泄露小。

### P11 三个科学问题（27 秒）

对应的三个科学问题是：

一，被加噪的量由随机、且与私有输入相关的黑箱产生时，ε-edge LDP 在什么条件下仍然成立，失效边界能否刻画；

二，curator 和节点输入都不可信时，能否让"执行规则—GS—噪声尺度"的绑定，由规则自动推导、在节点侧强制成立；

三，能否让 LLM 只负责设计、由可验证程序承担执行。

三个缺口对应三个动作：测不出、管不住、换不掉。

### P12 总目标（22 秒）

总目标是：**不改 DP 机制**，把保证从"靠 LLM 算对"变成"不依赖 LLM 算对"。

四个内容是一条链：隐私度量先测出缺口，执行约束把责任收回节点侧，程序解耦让保证与 LLM 无关，最后做成本与扩展评估。

### P13 内容一：隐私度量（34 秒）

内容一，隐私度量。口径上不看误差、看相邻变化：在只差一条边的相邻输入上取 Δ_LLM = |L(x) − L(x′)|，超过 GS 就是越界。相邻对只翻转私有邻居表的一位，公开图和消息保持不变，每个相邻对先用 Δf ≤ GS 自检。

判定上，重复输出一致且越界，就用 ε3 · Δ_LLM / GS 作为 ε 的下界；输出有抖动就追加采样，用 Clopper–Pearson 区间，下界超过 ε3 才计为越界。

审计只用已发布值和公开参数，属于后处理，不额外消耗隐私预算。

### P14 内容二：执行约束（30 秒）

内容二，执行约束。两个算例说明后果：控制器选 triangle 时，curator 若改选 3-star，ε3 实际约为 **90**；攻击者伪造 k 条发送者相同、列表为全部节点的消息，ε3 约为 **21**。

对策是三条：任务 ID、本地函数、投影方式、GS 公式作为整体下发，GS 由节点用公开 d̂max 自己算，不一致就拒绝执行；消息强校验，发送者必须在 N′(i) 中、每人只保留一条、列表必须等于 G′(发送者)；curator 只能下发"程序 + GS 声明 + 预算记账"，节点验证通过才执行。

### P15 内容三：程序解耦（30 秒）

内容三，程序解耦。链路是：curator 用受限 DSL 写程序，证伪器用小图穷举和随机、对抗搜索找漏洞，再做灵敏度静态推导，最后在节点本地确定性执行、加噪上报。

原则是"**LLM 提出、不让 LLM 认定**"：GS 数值、噪声采样、隐私记账全部由代码完成。

证伪器已经跑通：6 节点图上遍历全部翻转，14 秒内找出"k-star 不截断""非对称投影"两处漏洞。库外任务，比如 k≥4 的 k-star、路径计数，用来检验 LLM 设计程序是否真有价值。

### P16 创新点（20 秒）

创新点三条，分别落在问题、架构和方法上：首次量化 LLM 作为 DP 执行者的实测隐私损失；在 curator 与消息都不可信的设定下，把 ε-edge LDP 的保证责任收回用户侧；以及"LLM 提出 + 证伪器 + 灵敏度推导 + 运行时兜底"的可验证执行。每条都有明确的已有工作作对照。

### P17–P18 方法与路线（28 秒）

方法分形式化、构造、验证、实验四条线，分别回答能不能说清、能不能测到、能不能证明、能不能比较；每条线都写了失败时的退路。

技术路线五步：平台已经就绪，接下来依次是诊断、约束、解耦，最后是评估与扩展。

### P19 实验设置（18 秒）

实验用 CU 和 Do 两个图，四个任务 degree、2-star、3-star、triangle；ε 取 2 并按 ε1、ε2、ε3 拆分；对照 Naive 与 PSC；seed 0，在同一批噪声上配对比较，GT 跑 1000 次，LLM 每格 10 次，temperature 0。

### P20 前期结果（30 秒）

前期结果复现了论文的主结论：CU 上 degree，PSC 的平均相对误差是 **0.0167**，Naive 是 **1.15**，差两个数量级；GT 两列与论文 24 个格子的偏差都在 1% 以内，说明这个优势来自机制本身、与模型无关。

PSC 的执行误差很小，但不为零：3-star 和 triangle 各有 5/10 次运行受执行误差影响，这是剩余误差的主要来源。至于是否突破 GS，要由 P2 的配对审计回答。

## 四、预判问答（备用页支撑）

**Q1：审计会不会额外消耗隐私预算？**
不会。审计只使用已发布的值和公开参数，属于后处理；DP 的后处理性质保证不引入额外损失。我们做的是给出实测下界，不是再发布一个统计量。

**Q2：把 curator 当成不可信，是不是过度假设？**
LDP 的威胁模型本来就把服务器当成不可信方。PSC 里 curator 决定节点执行什么函数、用多大的噪声尺度，一旦它与控制器的选择不一致，噪声尺度就和函数脱钩——P14 的两个算例是 ε3 约 90 和 21。这是威胁模型能否自洽的问题，不只是工程加固。

**Q3：PSC 执行误差已经很小，这个工作是否多余？**
误差小是均值。3-star 和 triangle 各有 5/10 次受执行误差影响；P1 审计里 degree 的余量恰好为 0，Δ_LLM 等于 GS 等于 1，是靠 1119 个样本一次没数错才没越界。均值接近不等于每次算对，而 DP 的保证必须对每一次输入成立，不能建立在"这次恰好算对了"上。

**Q4：DSL 表达力不够、灵敏度推导过松怎么办？**
先用手工推导对齐三个任务的 GS；推导过松就让 LLM 迭代改写程序；无法静态推导的部分用运行时逐位裁剪兜底，保证构造上成立。表达力则用库外任务来检验——如果库外任务也需要人工补模板，那 LLM 设计程序就没有价值，这一点我会如实报告。

**Q5：如果审计最终没发现越界？**
主线不押在"找到越界"上。改用与输入相关的错误注入，验证审计器本身能不能测出已知的越界；同时给出可复现的构造反例，并把重点转到 degree、大图和弱模型。模块三提前启动，它才是主线。

**Q6：成本怎么控制？**
send 消息改由代码生成，约占输出 token 的 23%；设计步骤只依赖公开信息，可以缓存；禁止多节点合批、禁止按私有信息路由模型，避免旁路泄露。P1 约 3 美元，P2 约 5 到 8 美元，P3 在本地跑只需机时。
