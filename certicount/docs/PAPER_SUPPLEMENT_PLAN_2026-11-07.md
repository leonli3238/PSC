## 0. 结论：不需要精度 SOTA，但"修了 PSC 的缺陷"本身还不够

这篇论文的贡献类型是"**保证型**"（同类：DP 程序验证、DP 审计、可信执行），不是"**精度型**"。审稿人不会要求误差全表最低，但会追问下面四件事，缺一件就容易被定性为"对一篇论文的勘误 / 工程补丁"：

| # | 审稿人的问题 | 需要的证据 | 现状 |
|---|---|---|---|
| Q1 | 缺陷**真实存在且有后果**吗？还是只是理论上的漏洞？ | 真实模型下 PSC 被加噪的值 ≠ 规则函数的比例；可被利用的攻击；审计得到的 ε 下界 | 部分有（见 §1） |
| Q2 | 修复**真的有效**吗？ | 认证率 = 1、攻击成功率 = 0、审计无越界；GS 推导有定理 | 有 mock / 纯代码结果，**缺定理** |
| Q3 | 修复的**代价**能接受吗？ | 精度**不差于** PSC（非劣性检验）、调用与 token 更少 | 精度有纯代码结果；**缺真实模型主表** |
| Q4 | 是不是**只对 PSC 有用**？ | 库外任务、换模型、换规模；把缺陷与方法表述成一类系统的问题 | 库外任务只有 mock |

所以论文的主张应写成"**在不牺牲精度的前提下，第一个让 LLM 智能体做 LDP 计数时隐私保证与模型正确性无关的方法**"。
可以领先的指标是 CU@ε（认证效用）、认证率、攻击成功率、节点调用数，不是 RE。精度只需要证明"非劣于 PSC"，如果显著优于 PSC（3-star / triangle 目前优 27–29%）就作为附加收益写。

**定位要求（避免"补丁论文"）**：引言把问题写成"LLM 在私有数据上计算、系统再按规则函数的 GS 加噪"这一**类**设计的缺陷，PSC 只是代表实例；方法写成通用原则"设计与执行分离：LLM 产出可认证的程序，执行与隐私由代码保证"。

## 2. 需要补充的内容（非实验）

### 2.1 理论（必须，对应 C3）

1. **Soundness 定理**：对 DSL 中任意通过类型检查的程序 p，抽象解释推导的 \(\widehat{GS}(p)\) 满足 \(\max_{A_i \sim A_i'} |p(A_i) - p(A_i')| \le \widehat{GS}(p)\)。
   - 证明结构：对抽象域（max size、dsym、dsize、delta、range）逐个原语给出转移规则的引理，再对语法做结构归纳；
   - 写明三个公开事实开关（`symmetric_rows`、`self_not_in_private`、`rows_bounded`）各对应哪条前提；
   - 写明 `project` 的前提：投影顺序与 P 无关，同一次运行内所有 `project` 共用同一个顺序。
2. **端到端隐私定理**：程序模式 + 证书核验通过 ⇒ 每个节点满足 (ε1+ε2+ε3)-edge LDP，与 curator / LLM 的行为无关；自适应模式下选择是 ε2 发布的后处理。
3. **PSC 缺口的形式化**：给出反例构造，说明节点输出 L(x) ≠ f(x) 时，Lap(GS_f/ε3) 的隐私损失可以无界（例如 degree 任务，一侧数错 1 即超过 ε3）。这部分已有构造算例（`results/audit/2026-10-17/`），需要整理成命题。
4. **证书去循环（对应差距 G2）**：现在 `verify_certificate` 由节点用同一个函数重新推导 GS，审稿人会认为"自己验证自己"。两种做法任选其一：
   - 证书里带推导轨迹（每个子表达式的抽象值 + 所用规则编号），节点侧用一个独立的、只做逐条规则检查的小 checker 核验（目标 < 200 行，与推导器分开实现）；
   - 或把每条规则的转移编码成 SMT 约束，用 z3 对轨迹逐条验证。
   论文中报告 checker 的行数，并说明可信计算基（TCB）只包括 checker、解释器和 Laplace 采样。

## 3. 对比对象：五级阶梯 + 参照

所有实验都在**同一份噪声**（同 `[seed, i]`）上配对比较，比较对象固定为：

| 级别 | 方法 | 模式 | 节点 LLM | DP 保证是否依赖 LLM |
|---|---|---|---|---|
| L0 | GT-PSC（规则函数纯代码执行） | `gt-psc` | 否 | 否（理想参照，不是可部署方法） |
| L1 | PSC 原方法 | `baseline` | 是 | **是** |
| L2 | PSC + 三元绑定 + 消息校验 | `bind` | 是 | 是（输入层已闭合） |
| L3 | PSC + 代码守卫 | `guard` | 是 | 否（但只覆盖库内任务） |
| L4 | CertiCount 程序模式 | `program` | 否 | 否 |
| L5 | CertiCount + 自适应 / 程序池 | `adaptive` | 否 | 否 |
| 参照 | Naive、GT-TriTR、GT-DSL | | | |

说明：L3 是"不用 LLM 设计、只加守卫"的强对照，用来回答"既然守卫就能保证，为什么还要 L4"——答案在库外任务（E6）和精度（E3）。

## 4. 实验清单

每项给出目的、设置、指标、通过判据和调用量。**任何真实模型运行前先 `--dry-run` 报调用量和预估费用。**

### E1 缺陷存在性（动机，对应 C1）

- **E1a 历史结果重分析（0 次调用，最先做）**
  - 用 `analyze_cu.py` 回溯处理复现项目全部 exp1 结果，按模型（deepseek-v3、hy3-ioa、gpt-4.1-mini、hy4）× 任务 × 图统计：节点正确率、`exec_exact`、认证率、`llm_harm`；
  - 预期：强模型（hy3）triangle 认证率接近 1，deepseek-v3 只有 0–0.5。**这正好说明保证随模型变化**，是论文的第一张图。
- **E1b 节点错误率与度数 / 消息数的关系**
  - 设置：EE、PM 各按度数分层抽 60 个节点，节点 LLM 执行 triangle 与 degree 规则，各重复 3 次；
  - 指标：错误率随度数、消息条数变化的曲线（带 Clopper–Pearson 区间）；
  - 调用量：2 图 × 2 任务 × 60 节点 × 3 次 ≈ 720 次 / 模型；建议 1 个强模型 + 1 个弱模型（如本地 Qwen 小模型）。
- **E1c 灵敏度审计 P2 / P3**
  - 设置：沿用 `run_sensitivity_audit.py`；EE / PM 的 degree（余量为 0，最容易越界）分层 60 节点 × 4 个相邻对 × 两侧 × 3 次，标记的相邻对追加 50 次独立采样；
  - 指标：确认越界数（ε_lb > ε3，Bonferroni 校正）、max Δ_LLM/GS、余量分布；
  - 调用量：约 60 × 4 × 2 × 3 ≈ 1440 次 + 追加采样（每个被标记的对 100 次）；
  - 判据：找到 ≥ 1 个被确认的越界，就是论文最强的动机证据；没找到时，如实报告"未确认越界 + 错误率上界 + 余量为 0"，主张改为"保证无法事前确认"，并用 E2 的攻击补足。
- **E1d 审计的负对照与功效（0 次调用）**
  - mock 错误率 0 → 确认越界必须为 0；
  - 注入不同错误率（0.5%、1%、2%、5%）→ 统计审计能确认越界的比例，给出"检测到越界所需的最少采样次数"（power analysis，对应差距 G7）。

### E2 攻击实验（对应 C2）

- 现有：mock "完全服从"节点，L1 vs 防御后；
- 补充：
  1. 扩展到 L1–L5 全部级别（L4 / L5 对恶意规则天然免疫：节点只接受通过证书的程序）；
  2. 真实 LLM 节点（1 个强模型、1 个弱模型）在 CU、EE 上各 10 次，测实际成功率，与"完全服从"最坏情况并列报告；
  3. 新增一类"恶意程序"攻击：curator 提交一个读取私有邻居、但声称 GS 很小的 DSL 程序 → 证书核验必须拒绝；用 fuzz 生成的 GS 被低报的程序批量测试。
- 指标：攻击成功率、攻击者优势（TPR − FPR）、诚实运行的误拒率（必须为 0）；
- 调用量：真实节点部分按 `n × 次数 × 攻击类型` 计，CU 小、EE 大，先 dry-run。

### E3 精度主表（非劣性，对应 C4）

- 设置：6 张图（CU、Do、ML、CS、EE、PM）× 任务（degree、2-star、3-star、triangle、4-star）× L0–L5 + 参照，ε = 2；
  - 纯代码方法（L0、L4、L5、GT-TriTR）每格 1000 次；
  - L1–L3 需要节点 LLM，每格 ≥ 30 次（优先复用已有 exp1 结果，同口径不足的再补）；
  - L4 的程序**必须来自真实 LLM 设计**（E6 的产出），并与 GT-DSL 对照报告设计误差。
- ε 扫描：ε ∈ {0.5, 1, 2, 4}，只跑纯代码方法（0 次调用），画 RE–ε 曲线。
- 检验：
  - 主检验为**非劣性**：L4 / L5 相对 L1 的配对 RE 差，95% paired bootstrap 置信上界 ≤ 0（或预先声明的 δ，例如相对 5%）；
  - 次检验为优效性：Holm 校正后报告显著优于 PSC 的格子数。
- 写法：只在 LLM 方法（L1–L5）内加粗；与 TriTR 比输掉的格子照实保留，说明 TriTR 是可以收入程序库的估计量。
- 可选（冲精度）：把 TriTR 收入库并改进选择器，目标是缩小"固定最优设置 0.470 vs 实际自适应 0.570"的差距。**不作为论文成立的必要条件。**

### E4 认证效用 CU@ε（核心新指标，对应 C5）

- 定义：每次运行 \(\mathrm{CU}_r = \mathrm{Cert}_r \cdot \mathrm{RE}_r + (1-\mathrm{Cert}_r) \cdot 1\)，取平均；罚值 1 等于"直接答 0"的相对误差。附带报告：
  - 认证覆盖率 CC：认证运行的比例；
  - DCC：从任务描述到得到第一个通过的证书所用的设计调用数；
  - 每个认证答案的调用数：总调用数 ÷ 认证运行数。
- 设置：与 E3 同表，L1–L5 × 3 个模型（强 / 中 / 弱）；L1、L2 的认证率由 E1a 的回溯结果直接给出一部分，缺的格子补跑。
- 敏感性分析：罚值取 {0.5, 1, 2}，排序不变才能下结论；同时报告不加罚的 RE，避免被说成"自定义指标刷分"。
- 预期：L4 / L5 的 CU@ε = RE（认证率恒为 1），L1 的 CU@ε 随模型变差而上升。**这是可以写"best"的主指标。**

### E5 鲁棒性曲线（0 次调用，对应 C5）

- 设置：mock 节点注入 ±1 错误，错误率 ∈ {0, 0.5%, 1%, 2%, 5%, 10%, 20%}，CU、EE、PM × degree / 3-star / triangle × L1–L5，每点 100 次，同噪声；
- 指标：横轴为注入的错误率，纵轴为 CU@ε、RE、认证率；
- 预期：L3–L5 是水平线，L1 / L2 的认证率在错误率很低时就趋近 0（triangle 一次运行有 n 个节点，只要有一个出错就不认证）；
- 用途：与 E1a 的真实模型落点叠在同一张图上，说明真实模型落在曲线的什么位置。

### E6 智能体设计能力与库外任务（对应 C6，证明"智能体不可或缺"）

- **E6a 设计器评估（目标二，真实模型）**
  - 设置：`run_dsl_design_eval.py`，3 个模型（如 hy3-ioa、deepseek-v3、glm-5.2 或 gpt-4.1）× 6 个任务 × 10 次独立设计，温度 0.7，最多 5 轮；
  - 指标：接受率、首次通过率、平均轮数、GS 比、预算拆分一致率、独立语义测试通过率、证伪、设计误差（与 GT-DSL 配对）；
  - 调用量上限：每个模型每张图 6 × 10 × 5 = 300 次，一般只需在 CU 上设计（设计只看公开信息，与图无关），共约 900 次。
- **E6b 库外任务**
  - 任务：5-star、度二阶矩、聚类系数（复合查询）；若加了 wedge / 路径原语，再加 k-path；
  - 对照：PSC 对库外任务**没有**带 GS 的规则——它要么交给 curator LLM 自由写规则（L1，GS 由 LLM 给出，无保证），要么拒绝；L3 守卫因为没有绑定函数而不可用；
  - 指标：认证率、GS 比（相对手工最优）、RE、DCC；
  - 这是"智能体不可或缺"的直接证据：没有 LLM 设计器，这些任务只能等专家手写。
- **E6c 与 DP 程序验证 / 合成工具的对比（对应差距 G6）**
  - 至少做一张定性表：输入形式（自然语言 vs 已标注的程序）、是否自动推导 GS、是否支持图投影、节点侧能否核验；
  - 若时间允许，挑 2–3 个任务手工改写成 CheckDP / DPGen 的输入，报告能否通过、耗时多少。

### E7 认证正确性（对应 C3，0 次调用）

- 随机程序对拍从 1 万扩到 10 万，覆盖新原语；报告"推导 GS < 证伪器找到的最大差"的反例数（必须为 0）和平均松弛度（推导 GS ÷ 证伪器下界）；
- 独立 checker 与推导器交叉验证：同一批程序结论 100% 一致；
- 变异测试：对推导器的转移规则故意注入错误（如漏掉一项 dsym），checker / 证伪器必须拦下，报告拦截率。

### E8 消融（对应 C6）

| 消融 | 去掉的部分 | 预期影响 | 调用量 |
|---|---|---|---|
| 无反馈 | 设计循环不返回拒绝原因，只允许重新采样 | 接受率下降、轮数上升 | 同 E6a 的 1/3 规模 |
| 无证伪器 | 只靠推导器 | 认证仍可靠（证明在推导器），但失去"过松"诊断 | 0 |
| 无自适应 | L5 → L4 | 3-star / triangle RE 上升（已有：−24% / −29% 的收益消失） | 0 |
| 无绑定 / 无校验 | L2 → L1 | 攻击成功率回升（E2） | 0（mock） |
| LLM 设计 vs 随机程序搜索 | 用 `random_design` 替代 LLM 设计器 | **如实报告**：目前三角形上随机池 0.553 优于 GLM 池 0.663 | GLM 加大预算重跑：每任务 ≥ 10 次调用、温度 > 0 |

程序池结论如果仍是"LLM 不如随机搜索"，就把程序池移到附录，正文的 LLM 价值只靠 E6（自然语言 → 可认证程序、库外任务），不要在正文里主张 LLM 能发现更好的估计量。

### E9 成本与规模（对应 C7）

- 成本：每种方法每次运行的 curator / 节点调用数、token、墙钟时间；L1 的节点调用为 O(n)（triangle 为 2n+3，`send_by_code` 后为 n+2），L4 为 0，设计调用按任务缓存、跨运行摊销；
- 规模：program 模式是纯代码，可以跑到大图（真实大图或合成图，n = 10³–10⁵），报告 RE 与运行时间；L1 在大图上只做节点抽样估算调用量和费用（不需要真跑完）；
- 回应差距 G5（目前只到 453 个节点）。

## 5. 统计规范（所有实验通用）

- 同噪声配对：同 `[seed, i]`，各方法消耗随机数的顺序一致（已由 `test_every_mode_equals_the_reproduction_on_identical_noise` 保证）；
- 每格次数：纯代码 ≥ 1000，含 LLM ≥ 30（主表）/ ≥ 10（攻击）；
- 区间：paired bootstrap 95% CI；比例用 Clopper–Pearson；
- 多重比较：主表用 Holm，审计用 Bonferroni；
- 超参数隔离：margin = 0.1 是看过 EE 试跑后定的，正文要么在 EE 以外的图上报告，要么用留一图交叉验证重新选；
- 负对照：mock 错误率 0 的审计与攻击必须为 0；
- 预注册：在跑主表前把非劣性的 δ、主指标、罚值写进本文件并提交 git，避免事后挑选。

## 8. 论文里可以说 / 不可以说

可以说：
- 所有 LLM 方法中，唯一在任意模型错误率下认证率都为 1 的方法；CU@ε 全表最优；
- 节点 LLM 调用为 0，攻击成功率为 0（四类攻击 + 恶意程序）；
- 精度不低于 PSC（非劣性检验通过），3-star / triangle 显著优于 PSC（以 E3 的最终数字为准）；
- 第一个能为自然语言描述的库外计数任务自动给出可核验 GS 的智能体方法（投稿前完成文献核对后再用"第一个"）。

不可以说：
- 误差全表最低（triangle / 3-star 仍不如 TriTR，除非完成 E3 的可选项）；
- LLM 能设计出比人更好的估计量（程序池证据相反）；
- GS 推导"已被证明"（定理完成前只能说"经穷举与随机对拍验证"）；
- 真实模型下 PSC "已被观测到泄露"（除非 E1c 确认越界）。
