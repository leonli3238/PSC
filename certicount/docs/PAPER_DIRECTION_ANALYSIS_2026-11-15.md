## 1. 判断：用户的质疑成立，但需要区分两种价值

对于预先确定的 degree、k-star、triangle 任务，如果人工代码和 CertiCount 使用相同的估计量、预算、投影与噪声分布，两者的统计性能应当相同。把执行进程称为 agent，不会产生额外的统计信息或隐私保证。

当前 `program` 模式实际上已经这样做了：curator LLM 生成受限程序，节点调用确定性解释器，节点 LLM 调用为零。参见 `certicount/framework.py:227` 和 `certicount/agents.py:128`。它更接近“LLM 辅助编程 + 可检查的 LDP 执行系统”，而非依靠多个 LLM 协同推理完成计数。

因此，不应把论文目标设为“证明 agent 无法被代码替代”。任何已经实现的 agent 流程本身也是程序；应检验的是在明确的任务分布、信息条件和资源预算下，哪种自动化方式更有效。

需要分开回答：

1. **执行价值**：对于一个确定程序，系统是否按已分析的语义执行，且全部发布满足约定隐私模型？这部分通常不需要 LLM。
2. **设计价值**：面对未预先编写实现的新查询，能否减少人工工作、更快找到合格实现，或在同样搜索预算下得到更好的估计量？这才是 LLM 可能带来增益的环节。

“专家最终也能手写”不是自动化工作的否定理由，但论文必须报告自动化覆盖率、首次可用答案的成本、失败方式和泛化范围。若专家早已写好的参数化模板即可覆盖所有评测任务，设计价值就没有被充分检验。

**推荐主线：面向受限开放图查询的 LDP 程序合成，重点处理随机化输入的统计语义，并由可信执行内核承担隐私保证。** LLM 是待评价的候选生成器；是否需要多个 LLM agent，留给消融实验决定。

### 2.1 最值得发展的是“隐私通过，但统计失效”的现象

本次从 A3 原始设计记录重新汇总：61 个接受程序中，9 个仅使用公开含噪邻表 `N(...)`，没有读取私有邻表 `P`。这些程序包含：

```python
return comb(size(N(self)), 4)
aggregate: total
```

该 4-star 程序在原始结果中通过语义测试和证伪，第三阶段 GS 为 0，但 PM 上平均 RE 为 **30.0813**；对应 GT-DSL 为 **0.1531**。另有含噪邻表上的三角形计数程序，RE 为 **100.9365**。出处：`results/dsl_eval/A3_pm_design_8bthink_d10_oob/table.md:30` 及库内设计记录。

这里的 30、101 是按真值归一化的相对误差数值，不是“比基线差 30、101 倍”的比值。

原因可以定位到 `dsl/utility.py:52`：无噪声测试把公开行设为真实图，即 `N(self) = P`；这样的测试可以发现计数因子错误，却无法区分真实邻表与 RR 邻表的统计性质。

对于未经后续投影的二元 RR 邻接行，设翻转概率为 `q = 1 / (1 + exp(epsilon1))`，节点真实度为 d，则直接求和可得：

\[
\mathbb E[\widetilde d] = q(n-1) + (1-2q)d.
\]

例如 n=453、d=9、epsilon1=1 时，期望含噪度约为 126。把它直接代入组合数会放大假边带来的偏差；上述式子只描述原始 RR，后续投影还会改变分布，不能直接用它替代完整管线分析。

第三阶段 GS=0 并非这个案例中的隐私错误：固定已经发布的 DP 邻表后，不再访问私有数据的计算属于后处理。前面的 RR 与度数发布仍有隐私成本。[R11] 真正失效的是估计量对目标统计量的近似质量。

这提供一个具体研究问题：**如何让合成器理解“对原始数据正确的公式”，经过随机化输入、投影和聚合以后，未必还是一个可用的统计估计量？**

### 2.2 “库外”目前主要是相对 PSC 的旧任务表而言

`dsl/library.py:31` 已经有 `kstar_source(k)`，4-star 和 5-star 分别只是传入 4 和 5。提示词还直接给出了 `C(degree(node), k)`。

这些任务可以作为参数泛化或接口可用性测试，但不足以证明发现了新的查询结构。应区分：

- 参数外推：把 k=3 换成 k=5。
- 表述泛化：同一统计量采用不同自然语言表达。
- 组合泛化：已知原语以未见过的方式组合，且涉及预算、截断、聚合或复用。
- 结构泛化：新的图模式或访问结构，需要不同分解与统计校正。

论文的主要自动化证据应来自后两类；前两类保留为简单层。

## 4. 推荐主线具体做什么

候选题目：**CertiCount: LLM-Assisted Synthesis of Privacy-Certified Graph Queries with Noise-Aware Statistical Validation**。

题目中的 privacy-certified 需要可靠性定理支撑；statistical validation 指经过独立验证，除非确有定理，否则不写成任意图上的效用保证。

建议先聚焦三个研究问题：

1. 在相同工具、候选空间和资源预算下，LLM 能否提高未见查询结构上的合格程序产出率？
2. 显式跟踪随机化输入的统计性质，能否减少“通过隐私检查但误差极大”的程序，并泛化到未见图分布？
3. 图领域的灵敏度分析与可信执行，能否在不信任设计器的前提下提供明确、可组合的隐私保证？

### 4.1 把任务规格与估计程序分开

新增受限的查询规格 IR，描述目标图模式、计数约定、公开筛选条件、归一化方式和允许的误差。它描述“想统计什么”，不预先指定 DP 估计器。

自然语言由 LLM 或非 LLM 前端转换为 IR；基准中的 IR 由独立人员或规则校验。合成器从 IR 生成执行 DSL。这样才能分别评价自然语言理解错误、估计器设计错误和执行错误。

对小型图模式，目标真值可由通用枚举器按 IR 计算，而不必每增加一个任务就手写一个 DP 参考算法。即使拥有无隐私真值 oracle，也不等于已经拥有高效、低噪声的 LDP 实现；但这种区别需要在基准定义中写清楚。

目前 `designer.py:171` 对 `task=None` 会跳过语义测试，所以不能把任意未知任务“通过 GS”解释为“正确回答”。不支持的规格应明确拒绝。

### 4.2 将隐私检查与统计检查做成两个独立模块

隐私模块回答“发布这个程序的结果需要多少预算”；统计模块回答“这个结果估计的是什么、偏差与方差来自哪里”。二者不应共用一个含糊的 accepted 标签。

可以保留以下状态：语法合法、规格匹配、隐私条件满足、统计验证通过、已发布。对于有形式证明的属性，记录证书；对于有限样本检验，记录测试分布、误差区间和外推范围。

统计模块的第一步应复用已有 `dsl/search.py:115` 的完整 DP 管线评分，而不是另写一套与部署语义不同的模拟器。当前 `exact` 设计路径并未将这个评分作为接受条件；已有 `search` 只是在固定公开合成图上优化分数，也不能因此声称有泛化保证。

### 4.3 需要形成方法贡献，而不止增加一条过滤规则

仅加入“禁止 N(self)”或“RE 不能超过参考程序”的判断可以修复当前例子，但论文容易变成针对坏案例的补丁。更有研究价值的方向是：

- 为数据对象记录来源：原始私有量、RR 发布量、带噪度界、后处理量、已发布估计量，以及其对应的 `release_id`。
- 为可支持的表达式族跟踪期望、偏差界、方差或协方差信息。对未校正 RR 计数、非线性变换、共享随机量重复使用给出具体诊断。
- 让模型接收能定位原因的反例，例如“该式在零三角形稀疏图上，RR 假边导致系统性正偏差”，再做程序重写。
- 对已知原语使用可证明的估计器与转移规则；对超出理论覆盖范围的组合采用独立公开图验证，并明确不提供统一效用保证。

这些方案都是待开发的研究假设。成立的关键是形成一种可组合的图统计分析，且相对于 NAM/DPRD、已有 DP 合成器和一个简单的端到端模拟过滤器，展示额外的覆盖率、诊断能力或搜索效率。仅把三个现有模块并排摆放不构成足够的方法创新。

一个可研究的最小技术范围是：对 epsilon1>0、未投影、每条无向边独立随机化的 RR 发布，记录校正变量 `U_e = (Y_e - q) / (1 - 2q)`，其期望等于真实边指示变量；不同边对应的独立变量乘积可形成无偏模式估计，而同一发布变量反复出现时不能把二阶矩当作均值的平方。投影、数据依赖的选择和共享发布又会改变这些前提。[R8] 可以尝试为有限表达式族携带 `(敏感度, 数据来源, 期望或偏差界, 方差界, 发布依赖)` 的分析状态，让检查器定位哪些步骤破坏了估计性质。均值校正和独立乘积本身属于已有知识，新增价值须在可组合分析的证明与覆盖范围中体现。

这里还存在一个必须接受的结果：如果查询 IR 已经足以让确定性编译器直接生成所有合格估计器，那么 LLM 的作用可能仅剩自然语言前端。此时应把编译与分析作为技术贡献，并通过任务理解或使用成本实验评价 LLM，不能人为限制编译器以保住 agent 叙事。

不应要求每个程序都与参考程序预算拆分一致，也不应拒绝所有仅使用 DP 发布量的程序。合法的后处理估计器可能更优；要检查其统计性质，而不是检查它是否模仿参考答案。

### 4.4 将隐私可信基收敛到可审查的范围

当前 `verify_certificate` 在 `sensitivity.py:423` 再次调用同一个 `derive`。这可以阻止 curator 低报 GS，但不能独立发现推导器自身的错误。它不是逻辑上自动无效的“循环证明”，而是推导器也属于可信计算基。

建议为图 DSL 给出健全性证明，覆盖集合变化、求和域变化、投影替换、对称公开行和数据无关投影顺序。证书携带结构化推导轨迹，由小型 checker 检查每条规则；checker 的规则本身仍需证明，不能因为实现独立就自动获得正确性。

端到端证明应说明：公开参数与图性质由可信机制生成或验证，不能由恶意 curator 自行声明；解释器遵循被证明的语义；预算核验发生在发布前。拒绝、异常、日志和反馈也属于需要界定的输出渠道。

不要为 checker 任意规定“少于 200 行”以替代可信性分析。小型实现有利于审查，但代码行数不是定理。

## 5. LLM 增益应当怎样测

### 5.1 必须加入的强对照

| 对照 | 实现要点 | 排除的混淆 |
|---|---|---|
| 专家静态程序 | 与 CertiCount 相同机制、预算与输入信息；可部署的代码实现 | 确认计数改善并非来自把 LLM 换成代码 |
| 参数化模板库 | 任意 k 的 star、支持范围内的 moments 与组合 | 防止把改参数包装成新结构泛化 |
| 自然语言解析 + 已认证 DP 库 | 同模型只选择工具和参数，后端与 CertiCount 一致 | 检验自由生成程序是否优于语义路由 |
| 枚举、随机、约束搜索 | 同 DSL、同合法候选空间、同检查器与评分器 | 检验模型相对于程序搜索的增益 |
| 单次 LLM 生成 | 同基础模型、同提示信息、直接交给相同检查器 | 检验多轮反馈价值 |
| 同预算独立重采样 | 总 token、检查次数或时间与闭环相当 | 排除“多花预算就更好” |
| 现有 CertiCount exact / search | 当前无噪声门、当前完整管线打分 | 测量新增统计分析的独立作用 |
| PSC、可信代码守卫 | 保留原始执行与安全修复对照 | 衡量执行层问题，作为动机和定位 |
| DPGen / CheckDP 共同支持子集 | 明确编码、标注、相邻关系与适配成本 | 检验与程序合成、验证方法的实际关系 |

GT-PSC、GT-DSL 的“GT”名称不意味着不可部署。只要使用的是事先给定的参考代码，而不是测试集真值或最优参数 oracle，它们就是合理且必须保留的代码基线。额外拥有测试图真值的最优选择器才应标成 oracle。

不同算法成本结构不同时，不必强行用一个不公平的“相同调用数”指标。至少报告候选检查次数、总 token、总 CPU/GPU 时间和墙钟时间，并画成功率随资源增长的曲线。

### 5.2 泛化基准要比当前七个任务更有区分度

建议先做 20-30 个小型试验规格，正式研究扩到约 40-60 个规格、至少 4-6 个结构或组合家族。这些是建议规模，不是统计功效的替代。

| 层次 | 例子 | 实现要求 |
|---|---|---|
| 参数与表述 | 未见 k、不同问题措辞、同义描述 | 当前 DSL 即可作为起点 |
| 多项式与组合 | 度矩组合、多个计数的线性组合、归一化 | 核验恒等关系、截断语义与聚合系数 |
| 公开条件 | 公开节点分组上的计数、带公开权重的计数 | 需要新增带类型与敏感度规则的公开属性原语 |
| 新图结构 | 小路径、4-cycle 或其他少量模式 | 先确认可表达、可分析，必要时新增已证明的原语 |
| 交互工作负载 | 复用已发布统计量，回答后续问题 | 属于扩展路线，需要状态与发布依赖管理 |
| 不支持或有歧义 | 私有条件未经预算、未定义分母、DSL 不支持的模式 | 正确拒绝或明确澄清；不能强行给答案 |

训练示例、工具参考例、调参任务与测试任务按结构家族划分，不能把同一任务的十种改写当成十种结构泛化。自然语言理解与程序合成分开测：同时提供“正确 IR 输入”和“自然语言输入”两条评测路径。

至少留出一种未用于设计评分的图分布，例如用 ER/BA 评分，测试 SBM、随机几何图、极端 hub 图与真实图；公开测试图与真实评估图分开。模型不能根据真实图误差来选择最终方案。

## 6. 必须补充的实验

### E0：主张、预算与数据口径核对，优先进行

产出：主张-证据矩阵、预算追踪表、每种状态的定义、可重跑与仅历史保留结果清单。门槛：核心数值与预算逐项可追溯，之后才扩展主表。

### E1：直接检验“代码就够了”

先在当前任务上比较专家代码、参数模板、语义路由、当前 CertiCount，确认同机制执行的差异；再在留出的组合和结构任务上加入枚举搜索、同预算 LLM 重采样与反馈循环。

主指标：规格正确且隐私条件满足的产出率、独立评估中的可用结果率、首次合格程序成本、人工介入次数。专家的测试图 oracle 结果只作上界，不作可部署基线。

进入下一阶段的证据不是“LLM 写出了五阶 star”，而是在非平凡任务族上具有可重复、达到事先约定实际意义门槛的增益。若模板或搜索已同样好，转向验证器论文或审计论文，不继续声称 agent 必要。

### E2：隐私通过后的统计错误及其修复

首先复用 119 份草稿做离线回放。对照为当前无噪声测试、完整管线模拟过滤器、建议的来源与统计分析、完整反馈重写。已拒绝草稿仍应保留，不能只评价成功设计。

构造多种失败族：直接在 RR 假边上非线性计数、投影过强、私有量未经限制导致 GS 太松、聚合倍数错误、相关随机量被当成独立量、复合估计分母不稳定。后几种需要对应原语支持后再纳入，不能声称现有 DSL 已覆盖。

指标：有害程序漏接收率、有效程序误拒率、错误诊断类别、修复成功率、误差均值和尾部、搜索成本。还应加入正确的公开数据后处理程序作为负对照，避免方法退化为“看到 N 就拒绝”。

核心验收是新错误族和未见图分布上的效果。只拦住已知 9 个程序属于回归检查，不是研究结论。

### E3：端到端精度与泛化主实验

保持现有六张图用于历史可比性，再加入结构不同的合成图以及规模更大的真实图；对 epsilon 取若干预先确定的点，如 `{0.5, 1, 2, 4}`。复杂新查询先在可算精确真值的规模评价，不必让每个任务都上最大图。

LLM 主表必须来自独立生成的新程序，同时报告拒绝与失败。执行噪声重复和设计重复分别统计：一个程序执行 1000 次，仍然只有一次设计样本。

可从每任务、每模型 10 次设计的 pilot 开始，关键结论扩到 20-30 次独立设计；每个冻结程序先做 200 次纯代码噪声重复，主表按 MC 标准误需要扩到 1000 次。实际数量由 pilot 的方差与目标置信区间决定。

报告：MAE、RMSE/MSE、带明确近零真值处理的 RE、偏差、P90/P95、极端失败率、覆盖率，以及每个合格答案的成本。对零计数任务不要通过省略行规避 RE 分母问题。

非劣性容差和实用性阈值事先设定；按任务、设计聚类给区间，噪声重复作为内部层。若相同随机序列因程序调用路径不同而错位，应改用按阶段和节点索引的随机数带；仅相同 seed 不足以保证每阶段同噪声。

任务精度基线至少包括专家 DSL、GT-PSC、适用任务上的 TriTR/edge clipping；NAM/DPRD 在实现与相邻关系对齐后纳入适用子集。不能以“不是 LLM 方法”为由排除更强的代码估计器。[R8-R10]

若扩大到一般图模式，补充 LNC/PC 框架的适配性检查；若主张通信收益，补充 GroupRR。公开硬度界与 DP 估计度界不是同一假设，较新理论方法也不应未经实现就假定其有限样本精度优于所有现有方法。[R16-R17]

### E4：理论与验证可信性

必须补齐的理论内容：受限 DSL 的灵敏度健全性、固定公开历史下局部机制的保证、完整交互发布的预算组合，以及可信执行假设。[R11]

对于随机化输入的统计分析，选少量代表性表达式族证明期望或偏差/方差界即可，不要求一次覆盖任意查询。实验对照解析值、独立枚举和模拟值。

验证包括小图穷举、边界参数、嵌套投影、GS 为零、聚合系数、证书篡改、公开事实伪造和规则变异。扩大 fuzz 的价值是找错；“十万次没有反例”仍不是形式证明。

代码当前使用浮点运算和 NumPy Laplace 采样，数学实数语义与实际数值实现须区分。正式声称实现级纯 DP 时需要可靠采样与数值误差论证；已知审计工作能发现朴素浮点机制漏洞。[R12] 不需要为本次分析自行实现密码学或 TEE。

### E5：执行层隐私审计及强对照

现有 PM 8B 非思考配置，在联合校正表中四组共确认 49/158 个测试实例越界；各集合分别控制显著性时是 51/158。随机参考集是 4/60，而非 49/158。不要把经过筛选、迁移的集合混成总体发生率；还需核验集合间是否有重复的相邻对。

后续补强模型、匹配解码参数、不同图和任务；保留同模型直接调用精确本地工具的强对照。当前 thinking 与非 thinking 的温度、token 上限不同，不能把所有差异因果归于 CoT。

筛查和确认使用独立样本；检验统计量在确认样本上不能继续选择；统一多重比较范围。黑盒审计统计的是 `LLM(x) + noise` 的分布，不是把两次随机输出的最大差直接当成确定性全局敏感度。[R12]

加入恒定偏移的负对照：即使 L(x)=f(x)+c 总是答错，也可能保留相同敏感度。对于确定性标量 L 和固定尺度 b 的理想 Laplace 机制，隐私损失由相邻输入的 `|L(x)-L(x')|/b` 决定；这一点可作为动机命题。[R11]

所有结论明确节点 LLM 是否在可信本地边界内。若原始邻表已经发送到不可信模型服务，后续加噪不能撤回该次原始数据披露。

### E6：把收益来源拆开的消融

建议消融：无自然语言模型、只做路由、无反馈、同预算重采样、通用错误提示替代定位反例、无统计检查、只有端到端模拟评分、无来源信息、同一 agent 与角色拆分。

隐私检查的关闭实验应在公开/合成数据上做反事实评价，不允许把未验证程序部署到真实私有环境。去掉某个模块后如果只是减少计算预算，需要同时报告或匹配成本。

若多角色不优于单 agent 加工具，就保留单 agent。论文质量应来自技术与证据，而非角色数量。

### E7：规模、运行成本与使用成本

分别计量设计、检查、证书核验、DP 发布、聚合、通信量和内存。报告冷启动和缓存复用后的摊销成本；设计是否跨图缓存取决于 prompt 与公开参数，当前缓存不能直接假设对任意 n 通用。

先选择 `n=10^3, 10^4` 的代表点；`10^5` 只针对已证明资源可承受的路径。当前 RR 会处理大量潜在边并产生稠密公开图，纯代码执行并不等于线性可扩展：degree / star 与需公开噪声邻接图的任务应分别报告。[R9-R10]

如果“非专家可用”是主要卖点，补充小规模、预先定义任务的人类使用研究或专家干预日志。测量从需求到正确可运行程序的时间和错误；不能只用 token 少来推断用户更容易使用。DPCheatSheet 已对专家与非专家使用 LLM 实现 DP 的差异进行研究，应作为这条主张的近邻工作。[R15]

## 7. 隐私模型和指标必须先明确

当前 README 已区分按节点邻接向量的单比特变化与整张无向图的一条边变化。后者会改变两个端点的私有数据。在当前下三角 RR 与双端点报告结构下，保守关系级组合是：

\[
\epsilon_{\mathrm{relation}} = \epsilon_1 + 2\epsilon_2 + 2\epsilon_3.
\]

论文应明确主定义；如果声称整图 edge-LDP，就按这一口径或更紧且已证明的会计重新标定全部方法，不能仅更改表头。也不要把“按节点定义”写成保护整个节点及其全部边的 node-DP。

对于自适应流程，程序和参数选择只能依赖公开数据或已合法发布的信息；再次访问私有数据的费用继续记账。纯 DP 场景可以从保守的顺序组合开始，不必为了显得复杂而引入新的会计机制。更复杂的自适应参数选择已有 privacy filters/odometers 研究。[R13]

不建议以旧计划的 `CU@epsilon = Cert * RE + (1-Cert) * 1` 为主指标：Cert 的定义有概念问题，罚值可能让“拒绝”比诚实发布一个 RE>1 的结果更有利，并掩盖覆盖率。优先分别报告：

- 有理论支持的保证范围和假设。
- 程序产出率、支持任务覆盖率、拒绝率。
- 独立测试中的规格错误与统计失败。
- 所有成功发布结果的误差分布及失败成本。
- 黑盒审计的证伪结果、功效与适用配置。

不能通过只展示成功且低误差的程序得到“整体非劣”。同样，不能把“未发现审计越界”称为 DP 证明。

## 9. 其他值得考虑的方向

### 9.1 多轮图分析与发布复用：更适合保留 agent 叙事

让用户提出一连串有依赖的问题，planner 决定复用已发布信息、分解新问题、分配剩余预算、选择估计器或拒绝查询。可信运行时检查每一步，模型只能看到公开或 DP 输出。

例如用户先请求边数与 2-star，再请求度二阶矩，存在 `sum(d_i^2) = 2 * sum(comb(d_i, 2)) + sum(d_i)` 的恒等关系。若已经发布了相兼容的估计量，可通过后处理构造答案，不再访问私有数据；不同裁剪定义的统计量不能未经分析就当成同一目标。

真正的难点在发布依赖、相关噪声、查询等价性、崩溃后的幂等发布和跨轮会计。当前 `composite.py:153` 在每次 `run_composite` 新建账本，它是批内组合起点，不是持久会话系统。

必要对照是带缓存的确定性查询优化器、贪心/优化预算分配、单 LLM 路由、具有同样可信执行的 agent。仅比“每次重新生成 DP 数据”省预算没有说服力。[R5,R13]

适合走系统方向，但范围比当前单查询明显更大。节点仍可完全用代码，无需为了多智能体标签恢复节点 LLM。

### 9.2 图 DP 验证与编译：主动降低对 agent 的依赖

研究受限图程序在投影、私有集合迭代、随机化邻接行下的可组合分析，提供证明、反例与独立核验。LLM 只是一个程序来源。

优势是现有 `sensitivity.py`、解释器、证伪器可以直接积累；主要门槛是相对于已有类型系统和图统计框架确有新规则、新分析精度或新可表达范围。[R2-R4,R8]

如果最后发现 LLM 的设计贡献有限，但图领域分析本身扎实，这是一条比继续强调“agent 不可或缺”更自然的论文路线。

### 9.3 神经计算接入 DP 机制的审计与修复

把研究对象扩展为一类系统：神经模型处理私有输入，系统随后按预期函数的敏感度加噪。研究预处理行为改变如何影响真实发布分布，以及哪些结构性修复有效。

现有 Qwen 数据是起点。要形成独立论文，需扩展到多种计算任务、模型、输入表示和工具调用策略，给出可复验的失败分类与统计确认。与 DPrivBench 区分：这里测可执行发布机制，而不是让模型口头判断一个定理是否成立。[R7,R12]

可进一步用 LLM 提出语义有效的相邻输入，但其价值也必须与随机、启发式和已有黑盒搜索比较，以确认越界所需调用量为主要成本。相邻性由代码验证，不能由模型自述。

此路线能最大限度复用审计资产，但仅证明“小模型在长列表上数错”不够。强模型或工具基线消除了大多数问题，也应如实报告。

### 9.4 新的高效 LDP 图估计器：潜力高，风险也高

若追求精度或通信方面的算法贡献，可以研究某一新图模式、公开结构约束或新的受限工作负载，推导偏差/方差界并比较适用的强估计器。[R8-R10]

这个方向需要具体统计技术突破；LLM 可以辅助探索，但不能因它提出过公式就把算法发现能力作为结论。把已有 edge clipping、预算网格调参或随机池挑最优包装成新机制不够。

## 10. 建议的论文取舍

| 路线 | 与当前资产的连续性 | 主要新增难点 | 最主要的审稿风险 |
|---|---|---|---|
| 查询合成 + 随机化输入统计验证 | 高 | 有区分度的任务基准、统计分析、隐私证明 | 被认为是 DPGen/验证器加 LLM 前端 |
| 多轮可信查询规划 | 中 | 持久账本、发布依赖、优化基线与交互工作负载 | 简单查询优化器就能覆盖全部任务 |
| 图 DSL 验证编译 | 高 | 新的可组合分析和严谨证明 | 规则只是在重现已有敏感度公式 |
| 神经预处理 DP 审计 | 高 | 跨系统的实证广度、功效与反例发现 | 只有 PSC 的个案勘误或已知黑盒审计的应用 |
| 新图估计器 | 中低 | 新算法、理论界和适用强基线 | 搜索收益来自调参、测试集选择或不同隐私口径 |

选择第一条时，正文集中在“规格到程序、随机化语义、可信发布”这一条链，审计是动机；不要再把审计、攻击、程序池、复合查询、成本同时写成五个互不支撑的核心贡献。

也不应承诺某个会议一定可接收。以我对当前证据的判断，仅补更多固定任务运行不足以形成强方法论文；完成有区分度的自动化实验、图领域技术贡献与清楚的隐私论证后，才有评估论文质量的基础。

推荐马上做的研究决策是：**先问在专家模板、现有 DP 库和普通搜索都可用时，CertiCount 还解决了哪个未被解决的问题。** 将这个问题写成可被实验否定的假设，再决定是否保留 agent 为论文核心。
