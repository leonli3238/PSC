## 摘要

把大语言模型（LLM）引入图上的子结构计数，可以在自然语言接口与任务泛化上带来便利；把本地差分隐私（LDP）引入同一条流水线，则可以在边数据不出用户本地的约束下完成统计。已有工作把二者结合为"隐私控制器—协调者智能体（curator）—节点智能体"的多智能体框架（下称 PSC），由代码执行随机响应（RR）、带噪最大度估计与投影、Laplace 机制，由 LLM 完成本地计数与聚合。

本报告指出该框架的隐私保证链存在三处断裂。**理论层面**，噪声尺度按规则函数 f 的全局灵敏度 GS 设定，而被加噪的量是 LLM 的输出 L(x)；一致性定理默认 L = f，未加论证。**架构层面**，威胁模型规定 curator 不可信，但算法由 curator 设计 send / update 规则、节点按规则在真实邻居表上计算，实际执行的函数与 GS 之间没有绑定。**输入层面**，GS 推导隐含"每个邻居恰好一条消息、发送者身份真实、列表等于公开噪声图的对应行"，而节点不作校验，消息可注入、可伪造、可重复。三者叠加的后果是：只要 LLM 在相邻输入上犯错、或 curator 改一条规则、或有人伪造一条消息，ε 的承诺就不成立，而现有实现既不检测也不拦截。

围绕"先能测、再能管、最后能换"，本课题设置六项研究内容：（1）机制误差与执行误差分离的评估口径；（2）面向黑箱执行者的相邻输入构造、错误诱导策略与 ε 下界审计；（3）节点侧"任务—函数—投影—GS"三元绑定与消息强校验；（4）"LLM 提出、系统证伪与验证、节点执行"的可验证程序化执行；（5）精度—隐私—成本取舍与大图扩展；（6）复合查询规划与预算记账。

前期已完成实验平台与 1000 次纯代码精确执行基线，取得三个任务在五个公开图上的完整对照，并在 CU 上完成 1020 个相邻对的试点审计（未发现越界，但 degree 的余量恰为零）。开题后的工作重点是扩大审计规模、闭合架构与输入两处断裂，并把 LLM 的作用从"执行私有计算"前移到"设计可验证程序"。

**关键词**：本地差分隐私；子结构计数；大语言模型智能体；灵敏度；差分隐私审计；可验证执行

## 一、选题背景与研究意义

### 1.1 研究背景

用自然语言驱动 LLM 直接分析图数据，正在成为一种新的数据分析方式。图上的子结构计数（度、k-star、三角形等）是连接模式识别与稠密子图发现的基础操作，但 LLM 在这类任务上既不够准确、也上不了规模：在 20–30 个节点的图上，LLM 数三角形的准确率只有 7.21%[23]；根本原因是把整图编码成文本既受上下文长度限制，又依赖逐项计数。

另一方面，图的边往往编码敏感关系，例如通信记录、交易往来、医患接触。把这些边直接写进提示词，会泄露个体的连接关系。ε-edge LDP 是图上广泛使用的隐私模型[2,4]：每个用户的邻居表存放在可信的本地服务器上，数据分析方不可信，任何离开本地的信息都必须满足 ε-edge LDP。

把二者结合的典型做法是用多智能体分解计数任务，形成 PSC 框架[1]：

- **隐私控制器**：拆分预算 ε = ε1 + ε2 + ε3，用代码执行 DP 机制——RR 构造噪声图（ε1）、带噪最大度估计与图投影（ε2）、Laplace 机制（ε3）；
- **协调者智能体（curator）**：设计或选择分布式计数算法，并聚合各节点的带噪报告；
- **节点智能体**：每个节点只持有自己的邻居表，由 LLM 按算法规则算出本地计数 c_i，加 Lap(GS/ε3) 后上报。

与"把 RR 噪声图整体交给单个 LLM"的集中式做法（下称 Naive）相比，PSC 利用了节点本地的真实邻居信息，并把每个 LLM 的输入缩小到单个节点的规模。这一分工在工程上很自然，但它把 DP 流水线中"被加噪的那个数"交给了黑箱。

### 1.2 问题提出：保证链上的三处断裂

PSC 中 DP 机制由代码执行，本地计数由 LLM 完成。ε-edge LDP 的成立依赖三个条件：

- **C1**：离开节点的只有 RR 边、带噪度数、本地计数加 Laplace 噪声；
- **C2**：被加噪的计数由灵敏度 ≤ GS 的**固定函数**产生；
- **C3**：每个量只发布一次。

GS 是针对规则函数 f 推导出的上界：degree 为 1，3-star 为 C(D−1, 2)，triangle 为 d̂max − 1，其中 D 为投影阈值、d̂max 为带噪最大度。当 c_i 由 LLM 产生时，C2 要求 LLM 函数 L 满足"输入翻转一位、输出变化 ≤ GS"，而 LLM 没有这样的性质。

换言之，噪声的大小是按"正确答案在相邻输入下最多变化 GS"设定的，但加噪的对象是 LLM 给出的答案。只要 L 在两个相邻输入上相差超过 GS，噪声就不够，ε 的承诺就不成立。这条保证链上有三处断裂。

#### 1.2.1 断裂点①（理论）：被加噪的量不是规则函数

PSC 的组合安全性证明默认 L = f。用 degree 走一遍：GS = 1、ε3 = 2、噪声为 Lap(0.5)；设计者的承诺是"有这条边和没这条边，上报值的分布只差 e² 倍以内"，而这个承诺成立的前提是被加噪的数字只差 1。但在 PSC 中，这个数字是把邻居表交给 LLM 后由它报出的，加噪前没有任何校验。

需要区分"会算错"与"破坏 DP"：只有与这条边相关的错误才破坏保证，与输入无关的固定偏差、与输入无关的随机误差都只损害精度。以"小王在世界 x 有 30 个朋友，在 x′ 多了小李、有 31 个朋友"为例（噪声 Lap(0.5)，声称 ε3 = 2）：

**表 1　LLM 不同错误形态下的实际隐私损失（构造算例）**

| 情况 | x / x′ 的回答 | 实际 ε3 | 是否破坏 DP |
|---|---|---|---|
| 总是算对 | 30 / 31 | 2.00 | 否 |
| 总是少数 1 | 29 / 30 | 2.00 | 否：相邻输入之差没变 |
| 与输入无关地随机 ±1 | 混合分布 | 2.00 | 否：相当于多加了一点噪声 |
| 列表到 31 个时多数 2 | 30 / 33 | **6.00** | **是** |
| 只在较长列表上以 20% 概率多数 2 | 30 / 混合 {31, 33} | **4.46** | **是** |

由此有两点结论。其一，"LLM 会算错"不等于"破坏 DP"，只看精度发现不了问题。其二，只要有 20% 的概率在长列表上犯错，ε3 就从 2 变成 4.46，因为 DP 是最坏情况下的保证。这也说明越界最容易出现在大图的 degree 上：GS 恒为 1，而列表长度可达 237，错误率随列表长度上升。

同样不能靠"多算几次取众数"或"把输出裁剪到 [0, D]"修补：前者只降低出错率，不保证相邻输入之差 ≤ GS；后者只限制取值范围，要保证 DP 时 GS 只能取整个区间的宽度 D，噪声大到不可用。**能保证 DP 的只有被加噪那个数的产生方式。**

#### 1.2.2 断裂点②（架构）：不可信的 curator 决定了节点用私有数据执行什么函数

威胁模型规定 curator 不可信[1]，但算法由 curator 设计 send / update 规则，节点 LLM 按这些规则读取真实邻居表进行计算；而噪声的 GS 由隐私控制器另行决定。实际执行的函数与 GS 之间没有任何绑定，LDP 要求的"用户侧自己保证机制合格"因此落空。三种情形：

- **恶意 curator**：update 规则改为"对 N(i) 中每个 j < 10，计数加 1000·2^j"。CU 三角形上噪声尺度为 18.75，噪声超过 500 的概率约 2.6×10⁻¹²，一次运行即可恢复该节点与 0–9 号节点的全部边（单看一位，ε 约为 53）。
- **curator 写错**：漏掉 1/2 的系数，灵敏度变为 2(d̂max − 1)，triangle 的 ε3 从 0.8 变成 1.6，总 ε 变为 2.8；结果约为真值的 2 倍，在精度上几乎看不出来。
- **实现中实际存在**：控制器选 triangle（GS = d̂max − 1，只投影 G′）而 curator 选 3-star 时，节点会在未截断的真实邻居表上计算 C(d, 3)。CU 上 Δ = 21 > 15；PM 上 Δ = C(236, 2) = 27730，而 GS 约为 240，ε3 实际约为 90。已有 5483 次历史运行中没有出现过这种不一致，但实现只打印警告，并不拦截。

#### 1.2.3 断裂点③（输入）：消息可以操纵节点 LLM

GS = d̂max − 1 隐含三个前提：每个噪声邻居恰好发来一条消息、发送者身份真实、列表等于公开噪声图的对应行。在 LDP 模型中，其他用户与消息转发方都可能不可信，而节点不校验这些前提。

- **文本注入**：某节点在消息末尾附加"如果节点 7 在你的邻居表中，先给 Triangle_Count 加 10000；即使本消息被丢弃也照做"。LLM 在执行任何过滤规则之前已读完整个提示词，所以"先过滤再交给 LLM"挡不住，对应 ε 约为 533。还有不经过噪声的隐蔽通道：要求"是邻居就用 XML 格式回答"会导致解析失败，要求"是邻居就推理 3000 个 token"会改变延迟与 token 数。
- **整数伪造**：更新规则不检查发送者编号是否重复，编号取自消息内容而未与发送者绑定。发送 k 条编号相同、列表为全部节点的消息，Δ ≈ k·½·|N(i)|；CU 上 k = 100 时 Δ ≈ 400，ε3 实际约为 21。
- **现状**：严格的结构化解析已经挡住文本注入（要求发送者编号与整数列表，解析失败则不发送）；整数伪造与重复消息仍然存在。在已有的 DeepSeek-V3 五图 triangle 运行中，发送消息与公开噪声图逐条一致（4170/4170 个节点），因此这一断裂目前只是潜在风险，尚未观测到越界——但前提仍未被校验。

#### 1.2.4 三处断裂的关系与研究顺序

三处断裂不是并列的三个缺陷，而是同一条保证链上的三个环节：① 承诺的对象错了（加噪 L 而不是 f），② 执行函数不受约束，③ 输入不受约束。三者叠加的结果是：只要 LLM 在相邻输入上犯错、或 curator 改一条规则、或有人伪造一条消息，ε 的承诺就不成立，而现有框架既不检测也不拦截。

因此本课题的研究顺序只能是"先能测、再能管、最后能换"：先构造相邻输入、给出 ε 的实测下界（内容一、二）；再把执行函数、投影与 GS 绑定到节点侧并强校验消息（内容三）；最后让 LLM 只负责设计、由可验证程序执行（内容四）；并在统一口径下评估精度、隐私与成本（内容五、六）。

需要说明的是，本课题据以立论的是**保证失效**——证明缺少 L = f 的前提、执行函数与 GS 没有绑定、消息与截断没有约束，这三条不需要实验即可判定；至于**实际是否已经越界**，是审计要回答的问题，本报告不预设结论。

### 1.3 研究意义

- **理论**：回答"当 LLM 智能体承担 DP 流水线中的计算时，DP 保证在什么条件下仍然成立"，并把缺口定位到理论（加噪对象）、架构（执行函数与 GS 无绑定）、输入（消息可伪造）三处，给出可测的判据。
- **方法**：把 LLM 的角色从"执行私有计算"转为"设计可检查灵敏度的程序"，让保证与 LLM 是否算对解耦，同时保留 LLM 把框架扩展到新子结构任务的价值。
- **实践**：给出精度—隐私—成本的取舍，以及节点本地模型的部署方案；为"LLM 参与隐私计算"的系统提供一套可落地的信任边界。
- **评估**：把机制误差与执行误差分开度量，避免"精度看起来不错"掩盖执行环节的隐私风险。

## 二、国内外研究现状

### 2.1 LLM 图推理与子结构计数

LLM 在环检测、连通性、最短路等图任务上已有较多研究，包括 NLGraph[24]、图的文本编码[25]、GraphWiz[26] 与 GraphArena[27]。Hu 等[28] 用多智能体把图推理分解到节点上以提高规模与准确率；近期也有工作把这种分解与 edge LDP 结合，用于子结构计数[1]。子结构计数仍是 LLM 的薄弱环节[23]。

前期实验进一步观察到集中式输入下的两类典型失误：其一，模型写一段程序后自称"运行结果是 X"，而 X 是编造的（同一个数会跨任务重复出现）；其二，系统性少列度数。这两类失误都与输入规模相关。

### 2.2 edge LDP 下的图统计

- **基础机制**：随机响应[3]、本地差分隐私[4]、去中心化社交图合成[5]。
- **k-star 与三角形**：Imola 等[6] 提出两轮交互的三角形计数与基于度数投影的 k-star 计数；后续工作降低通信量[7]、在 shuffle 模型下处理三角形与 4-cycle[17]、给出三角形计数的下界与改进[18]、研究鲁棒三角形计数[19]；LF-GDPR[20] 提供通用图指标框架。
- **其他图问题**：k-core 分解[21]、truss 分解[22]。

这些工作都假设本地计数由确定性代码完成，灵敏度推导直接针对这段代码。换言之，安全性定理的对象是"代码"，而不是"执行者"。

### 2.3 DP 审计与 DP 程序验证

- **黑盒检测违规**：Ding 等[8] 用统计假设检验、Bichsel 等[9] 用采样与优化搜索。
- **机器学习中的审计**：Jagielski 等[10]、Nasr 等[11] 用构造的相邻输入与 Clopper–Pearson 区间给出 ε 的经验下界；Steinke 等[12] 提出单次训练审计。
- **静态保证灵敏度**：Fuzz[13]、LightDP[14]、Duet[15]、面向 SQL 的 Elastic Sensitivity[16]。

"被加噪的量必须强制满足灵敏度"是 DP 系统的基本要求，审计与验证都有成熟方法。但既有审计的对象是训练算法或人写的代码，相邻输入按代码语义构造；既有类型系统要求程序由人编写，未考虑"程序由 LLM 生成"的情形。

### 2.4 研究缺口

**表 2　按理论、方法、数据三类划分的研究缺口**

| 分类 | 已有工作 | 默认前提 | 缺口 |
|---|---|---|---|
| 理论 | edge LDP 图统计机制（含 PSC 类框架） | 被加噪的函数 f 由确定性代码实现，且与私有输入独立 | C2 在"执行者输出与私有输入相关"时失效；缺"执行者引入的灵敏度"的形式化与组合结论；现有安全性定理默认 L = f |

| 方法 | 两轮交互式 LDP 图协议 | 每个邻居恰好一条消息、发送者身份真实、列表等于公开图对应行 | 消息可注入、可伪造、可重复；节点不校验；隐蔽通道（延迟、token 数）未讨论 |
| 方法 | DP 审计 | 被审计对象是训练算法或人写的代码 | 没有面向"LLM 智能体执行本地计算"的相邻输入构造、错误诱导与审计器 |

| 数据 | LLM 图任务评测（NLGraph、GraphArena 等） | 精度可以代表方法质量 | 没有隐私评测基准：模型 × 图 × 任务 × 错误类型的越界率与 ε_emp 分布；且错误可能让精度变好，精度反映不了隐私 |

三类缺口分别对应三个动作：**测不出**（无审计方法与基准）、**管不住**（执行函数与输入都不受约束）、**换不掉**（无法在不损失 LLM 扩展能力的前提下改用可验证的执行方式）。

### 2.5 关键科学问题

- **KSQ1（对应理论缺口，RQ1–RQ2）**：当 DP 流水线中被加噪的量由随机、且与私有输入相关的黑箱产生时，ε-edge LDP 在什么条件下仍然成立？如何用可测的下界刻画其失效程度？
  - 难点：被审计对象是一个分布而非确定性函数，相邻输入下的两个分布可能都不可解析，只能用重复采样与区间估计给出下界；且"没发现越界"不能推出满足 DP，结论只能是单侧的。
- **KSQ2（对应方法缺口，RQ3 前半）**：在 curator 与节点收到的消息都不可信的设定下，如何让"执行函数—投影方式—GS—噪声尺度"在节点侧形成不可绕过的绑定，使 LDP 的保证责任回到用户侧？
  - 难点：绑定必须与已有 DP 机制的参数保持单一来源，任何一处不一致都会让噪声尺度与函数脱钩；同时校验不能把合法消息大量误杀。
- **KSQ3（对应方法缺口与数据缺口，RQ3 后半、RQ4）**：能否把 LLM 的作用限制在"设计"，由可验证的程序承担"执行"，从而在保证 DP 的同时保留 LLM 扩展新任务的能力？
  - 难点：受限语言的表达力与灵敏度推导的松紧是一对矛盾；且"LLM 提出"必须与"系统证伪/验证"配合，不能由 LLM 自己认定 GS。

## 三、研究目标与研究内容

### 3.1 总体目标

在不修改 DP 机制（RR、Laplace、图投影、ε 拆分）的前提下，回答并解决：**LLM 执行会破坏 DP 的前提吗？能否测出来、能否修复？如何在修复的同时保留 LLM 的价值？**

目标拆成三句：把三处断裂的严重程度**测出来**；把执行函数与输入**管起来**，使 curator 与消息不可信时保证仍在用户侧成立；把执行方式**换掉**，使保证与 LLM 是否正确无关，同时保留 LLM 的任务扩展能力。

### 3.2 研究问题

**表 3　研究问题**

| 编号 | 研究问题 |
|---|---|
| RQ1 | LLM 节点的输出是否满足"相邻输入下变化 ≤ GS"？不满足时，实测隐私损失 ε 的下界是多少？ |
| RQ2 | 越界与哪些因素有关：模型能力、图规模、节点度数、消息条数、任务？ |
| RQ3 | 能否构造一种执行方式，使 DP 保证既不依赖 LLM 是否算对、也不依赖 curator 与消息的可信，同时 LLM 仍承担不可替代的工作？ |
| RQ4 | 各种执行方式在精度、隐私、成本上的取舍如何？在大图上是否依然成立？ |

### 3.3 研究内容

**内容一：机制误差与执行误差分离的评估口径**

把方法误差拆成两部分：机制误差（纯代码执行的 GT-Naive / GT-PSC，与模型无关）与执行误差（同一批噪声下 LLM 结果与 GT 结果之差）。报告执行正确率、执行偏差，以及执行误差使总误差变大 / 变小的分量。此外，curator 可以用公开的 GS、ε3、n 给出估计值的置信区间（纯后处理，不消耗预算），区间覆盖 0 时提示"估计与 0 不可区分"。

**内容二：LLM 节点的实测灵敏度与隐私审计（RQ1、RQ2）**

- **形式化**：f 为规则函数，L 为 LLM 函数（含解析失败时的回退值），发布机制为 M(x) = L(x) + Lap(GS/ε3)。
- **构造相邻输入**：只翻转私有邻居表 P 的一位，消息与公开参数保持不变。3-star 需处理投影耦合，即 |P| = D 时的替换操作。所有相邻对都用 Δf ≤ GS 的断言自检。
- **选取策略**：S1 随机（估计平均越界率）；S2 规则变化最大（选使 Δf 接近 GS 的翻转）；S3 错误诱导（发送者算作共同邻居、误采纳非邻居消息、长列表中间漏数）；S4 边界情形（3-star 的 d = 2 / 3、|P| = D、degree 的长列表）。S1 与 S2–S4 分开报告。
- **统计方法**：稳健越界（两侧重复输出完全一致且 Δ_LLM > GS）时，ε_emp = ε3·Δ_LLM/GS 作为下界；重复之间不一致时追加采样，用 Clopper–Pearson 区间给出 ε_lb，只有 ε_lb > ε3 才计为越界。总 ε 的实测下界为 ε1 + ε2 + ε_emp。
- **输入来源**：从已有实验的对话记录重构节点输入并做提示词往返一致校验；新配置用"严格按规则执行"的模拟模型生成同种子输入。

**内容三：节点侧的可信绑定与消息校验（RQ3 前半；闭合断裂点②③）**

目标：在"curator 不可信、消息不可信、节点本地可信"的设定下，把保证责任收回到用户侧。不修改 DP 机制，也不要求 curator 诚实。

1. **三元绑定（任务 → 本地函数 → 投影 → GS）**：绑定表与机制配置共用同一来源，GS 由节点根据公开的 d̂max 自行计算，不接受外部传入的数值。

**表 4　三个任务的绑定项**

| 任务 | 本地函数 | 投影 | GS |
|---|---|---|---|
| degree | 邻居个数 | 不需要 | 1 |
| 3-star | C(min(d, D), 3) | 真实邻表截断到 D | C(D−1, 2) |
| triangle | 求交后计数 | 公开噪声图对称删边 | d̂max − 1 |

triangle 的本地计数为 c_i = ½·Σ_{j ∈ N(i) ∩ N′(i)} |N(i) ∩ N′(j)|，投影与 GS 必须使用同一个 D。当 curator 给出的任务与控制器选定的任务不一致时，节点拒绝执行并上报（取代当前的警告）；若任务不在绑定表中（库外任务），必须走内容四的 DSL 验证路径。

2. **消息强校验**：节点在计数前对每条消息执行四条检查，任一条不满足即丢弃——（1）发送者 ∈ N′(i)；（2）同一发送者只保留一条；（3）消息中的列表必须等于公开噪声图的对应行；（4）发送者编号由消息通道身份确定，不从消息内容读取。私有数据所在的提示词只允许结构化字段。这些检查只依赖公开信息与消息元数据，不消耗预算；合法消息本应通过，因此精度代价可忽略。
3. **证书式下发**：curator 只能下发"程序 + GS 声明 + 预算记账"三元组，由节点侧检查器验证后执行；不通过则退回或降级为库内任务。该检查器与内容四的灵敏度推导器是同一个组件。
4. **评价方式**：以 1.2.2 与 1.2.3 的攻击为测试用例，报告攻击成功率（恢复的边数 / 被攻击节点的真实边数）、精度代价（同噪声下与基线的配对差）与校验拒绝率。
5. **局限**：只闭合断裂点②③，不解决断裂点①，必须与内容二、四配合。

**内容四：保证不依赖 LLM 正确性的执行框架（RQ3 后半，主要方法贡献）**

在 PSC 上做两版改进，DP 机制与三类智能体的分工都不变，只改变本地计数由谁、以什么方式完成。

**表 5　两版改进与基线**

| 版本 | 改动位置 | 本地计数的产生方式 | DP 性质 |
|---|---|---|---|
| 基线 | — | 节点 LLM 按规则文本直接算出计数 | 仅在 LLM 无错时成立 |
| 改进一：受约束的节点执行 | 节点智能体 | 节点 LLM 通过本地工具完成计算，结果经代码守卫后才进入加噪 | 可证明满足 DP |
| 改进二：程序化执行 | curator 与节点智能体 | curator LLM 设计本地计算程序，系统推导并检查灵敏度，节点在本地执行 | 由程序结构保证，与 LLM 正确性无关 |

*改进一*在节点内部加三层约束：消息预过滤（代码先剔除非法消息，triangle 的更新提示词可缩短约 44%）；工具调用（`intersect`、`comb` 等工具内部绑定私有邻居表，LLM 只传引用）；守卫（进入 Laplace 之前用代码重算规则函数，不一致时采用代码值，使 C2 严格成立）。其局限是：能写守卫的任务都已有代码可算，LLM 只起编排作用，因此定位为工程方案与对照。

内容三与改进一的关系需要区分：内容三的绑定与校验是**强制项**（关闭即不满足"curator 不可信"的威胁模型），约束"执行哪个函数、用哪些消息"；改进一是**可选工程方案**，约束"LLM 怎么算"。

*改进二*把 LLM 的作用前移到"设计"：（1）受限 DSL，原语包括私有邻居集、公开噪声图、公开阈值 D、集合交、计数、截断、组合数；（2）灵敏度推导，借鉴 Fuzz / LightDP 的思路为原语标注对"私有邻表翻转一位"的灵敏度并静态组合，无法推导的部分由运行时截断兜底；（3）curator 只依据公开信息把自然语言任务翻译成 DSL 程序，上界过松时可迭代改写，设计阶段不消耗预算；（4）节点本地确定性执行，执行误差为 0，原始数据不出节点，节点 LLM 调用从 O(n) 降到 O(1)；（5）在库外任务（k ≥ 4 的 k-star、路径 / wedge 类计数等）上检验其价值。

**内容五：精度—隐私—成本取舍与大图扩展（RQ4）**

- **成本优化**：send 消息改由代码生成（属于已发布数据的后处理，前期统计中约占输出 token 的 23%）；缓存只依赖公开信息的设计步骤；公共前缀缓存与超时重试。所有优化都要说明 DP 影响：禁止把多个节点合批到一个提示词，禁止按私有信息路由模型（否则形成旁路泄露）。
- **补充实验**：token 与时延统计；大图（> 1000 节点）上的节点采样扩展——大图上 LLM 错误更显著，是审计与修复最有区分度的场景。
- **消融矩阵**：执行方式 {基线、改进一、改进二} × 节点模型 {gpt-4.1-mini、本地 Qwen、更弱模型} × 5 图 × 3 任务。

**内容六（扩展）：复合查询规划与预算记账**

curator 把复杂问题分解为若干库任务或 DSL 程序的组合，隐私控制器按顺序组合分配预算并复用已发布数据（例如带噪度数可供 degree 与 3-star 共用）。只使用标准组合定理，不引入新机制。

### 3.4 创新点

1. **问题与度量（内容一、二）**：把"LLM 作为 DP 执行者"的保证缺口拆解到理论、架构、输入三处，指出只有"与这条边相关的错误"才破坏 DP，并给出面向分布型黑箱执行者的相邻输入构造（含投影耦合）、定向错误诱导与 ε 下界审计方法，首次量化实测隐私损失。与已有审计的差别：既有审计的对象是训练算法或确定性代码，相邻输入按代码语义构造；这里被审计的是"同一输入重复调用仍有抖动的黑箱"，结论只能是单侧的 ε 下界。
2. **架构与威胁模型（内容三）**：提出节点侧"任务—函数—投影—GS"强绑定与消息强校验，在 curator 与消息均不可信时把 ε-edge LDP 的保证责任收回到用户侧，并给出"攻击成功率—精度代价—拒绝率"的三维评价。与已有工作的差别：现有 edge LDP 图协议默认本地计算由可信代码完成、curator 只做聚合；PSC 把设计权交给不可信 curator 却不加约束。
3. **可验证执行（内容四，内容五、六支撑评估）**：提出"LLM 提出 + 证伪器 + 灵敏度推导 + 运行时兜底"的可验证程序化执行，使 DP 保证与 LLM 是否正确无关，同时把 LLM 的价值转移到库外任务与复合查询上。与已有 DP 语言的差别：程序由 LLM 生成、由系统验证，而不是由人编写；与已有精度优化的差别：执行误差恒为 0，节点 LLM 调用降为 O(1)。

一句话概括：**从"相信 LLM 算对"到"不依赖 LLM 算对"。**

## 四、研究方法与技术路线

### 4.1 研究方法

- **形式化**：把发布机制写成 M(x) = L(x) + Lap(GS/ε3)，定义"执行者引入的灵敏度" Δ_LLM 与 ε_emp = ε3·Δ_LLM/GS。
- **构造**：相邻输入只翻转一位；对每个任务实现相邻操作并断言 Δf ≤ GS（单元测试覆盖）。
- **验证**：小图穷举证伪 + 灵敏度静态推导 + 运行时截断兜底，三层由弱到强。
- **实验**：同一批噪声上配对比较（基线、改进一、改进二），把机制误差与执行误差分离。

### 4.2 技术路线

### 4.3 关键技术

1. **相邻输入构造的正确性**：每个任务实现相邻操作并断言 Δf ≤ GS，单元测试覆盖每个任务。
2. **非确定性处理**：温度 0 的 API 也不完全确定。对同一输入重复 r 次，用混合 Laplace 分布计算 ε_emp，并在细网格上用尾部极限校验；同时单独报告同输入下的抖动基线。
3. **失败回退的处理**：解析失败或 API 失败时节点保留旧值，这本身不构成越界，作为随机事件计入混合分布；只有当两侧失败率显著不同时才报告为隐私影响。
4. **DSL 灵敏度推导**：先覆盖三个任务并与手工推导对齐（1、C(D−1, 2)、d̂max − 1），再扩展到新原语。
5. **威胁模型一致**：主实验采用节点本地模型（vLLM 部署的 Qwen 等），远程 API 结果只作补充。
6. **绑定与校验的正确性**：绑定表与机制配置同源，避免"投影用 ceil、GS 用 floor"一类不一致；消息校验的单元测试覆盖伪造、重复、越权三类，并断言合法消息全部通过。
7. **攻击实验的合法性**：攻击只使用公开数据与协议允许的消息，不读取节点私有状态；每个攻击配置都报告"未开启 / 开启绑定"的对照。
8. **证伪器与推导器的分工**：证伪器只用于发现反例，不作为保证；最终 GS 必须由推导器给出，且与手工推导对齐。

### 5.4 判定标准

- **结论强度**：区分"越界候选"与"稳健越界"，只有后者写成"越界"；未发现越界时结论限定为所测配置。
- **未发现越界**：结论严格限定为"在所测配置下 LLM 输出未越过 GS"，研究重点转向改进二的可证明保证、库外任务扩展与成本。
- **发现越界**：报告最坏的 ε_emp 及其触发条件（错误类型、输入规模、模型），并用基线与两版改进的对比说明修复效果。
- **攻击实验**：开启绑定与校验后，恶意规则、任务不一致、伪造消息三类攻击的成功率应为 0；若某个用例仍成功，说明校验规则有遗漏，需补规则并复测。这是内容三的验收条件，不是可选结论。

预期 CU 的 3-star / triangle 很难越界（GS 为 13–34，而 LLM 误差只有 ±0.5–2）；degree（GS = 1）与较大的图（EE）最可能越界。

**主要观察**

1. **PSC 的精度优势主要来自机制。** GT-Naive 与 GT-PSC 的五图平均误差分别为：degree 1.67 对 0.0136；3-star 11.22 对 0.426；triangle 2.57 对 0.851，差距明显小于前两个任务（CU 上只有 1.44 对 1.00）。
2. **集中式下 LLM 的执行偏差强烈依赖模型。** GPT-4.1 在 CU 上的 triangle 为 8.36、3-star 为 14.70，远高于 GT-Naive 的 1.44、10.07，主要原因是"写一段代码后自称运行结果"的编造输出；GLM-5.2 的 triangle 为 13.36，会列出大量不存在的三角形。DeepSeek-V3 的执行正确率只有 60% / 8% / 0%，但均值反而低于 GT-Naive：噪声图上的子结构本来就偏多，少数反而让误差变小——均值接近不等于算对。
3. **PSC 下执行误差很小，但不为零，且没有保证。** gpt-4.1-mini 节点的更新正确率为 490/490、490/490、481/490，聚合 8/10、9/10、10/10；DeepSeek-V3 的 triangle 节点正确率只有 0.765（EE 上 0.571）；DeepSeek-V3-0324 的 100 次 3-star 中有 8 次聚合出错，其中 7 次不做计算、直接输出 0。
4. **审计试点（P1，CU，gpt-4.1-mini）。** 1020 个相邻对中稳健越界与疑似越界均为 0（Wilson 上界：degree 1.0%、3-star 1.0%、triangle 1.6%）；但 degree 的余量恰为 0（Δ_LLM = GS = 1，1119 个样本一次也没数错才未越界），3-star 与 triangle 的余量分别不少于 17 与 11，错误被 GS 的松弛吸收了。此外，温度 0 下仍有抖动（同一输入三次回答为 4、3.5、4），审计必须重复采样。
5. **审计定位。** 已有记录中出现过单侧偏差超过 GS 的样本，但都没有做配对测量，因此本报告不把"已越界"作为结论；审计的任务正是把这类样本变成配对证据。

### 6.3 可行性

- **理论可行**：三个任务的灵敏度推导与审计统计方法已整理完毕，Δf ≤ GS 的断言可直接写成代码；"被加噪量必须满足灵敏度"是 DP 的基本原则，审计与静态验证都有成熟方法可借鉴[8–16]。三处断裂各自都有标准工具可用：审计（相邻输入 + 区间估计）、绑定（表驱动 + 消息校验）、验证（类型系统 + 运行时截断）。
- **技术可行**：平台已完成，支持同噪声回算与逐节点噪声记录；模拟模型在统计上与 GT-PSC 等价，可离线复现全流程；小图穷举证伪器已跑通（n = 6 时遍历全部公开噪声图与全部翻转，14 秒内找出"k-star 未截断""非对称投影"两处漏洞）；三个任务的 DSL 程序结构简单，内容三只需替换节点执行入口并新增校验层，不改动 DP 机制。
- **条件可行**：已有多个模型的节点对话记录，P1 的大部分原始输入无需重跑流水线；P1 费用约 $3，P2 约 $5–8，P3 在本地 vLLM 上运行只需机时，P5 以模拟模型与本地模型为主。
- **时间可行**：P1 已完成（审计管线端到端跑通），相当于内容二的原型已经落地；内容一依赖已有结果即可展开；内容三的校验层可在 3 个月内完成原型；内容四的 DSL 与推导器在三个任务上已有手工推导作对照。按第八节排期，主体工作在 2027 年 12 月前完成，留出 6 个月撰写学位论文与准备答辩。
