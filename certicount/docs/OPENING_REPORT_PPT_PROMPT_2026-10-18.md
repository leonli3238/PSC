## 第 4 页 ε-edge LDP 与 PSC：DP 由代码做，计数却由 LLM 做
- 画一张流程图（三类角色 + 数据流）：
  - 隐私控制器：拆分 ε = ε1 + ε2 + ε3，用代码执行 DP 机制——RR 构造噪声图（ε1）、带噪最大度估计与图投影（ε2）、Laplace 机制（ε3）。
  - curator（协调者智能体）：设计或选择分布式计数算法，聚合各节点的带噪报告。
  - 节点智能体：每个节点只持有自己的邻居表，由 LLM 按算法规则算出本地计数 c_i，加 Lap(GS/ε3) 后上报。
- 对比 Naive（集中式）：把 RR 噪声图整体交给单个 LLM；PSC 利用节点本地真实邻居信息，并把每个 LLM 的输入缩小到单节点规模。
- 图中用两种颜色区分"代码执行"（DP 机制，深蓝）与"LLM 执行"（本地计数、聚合，橙色），为下一页埋伏笔。
- 备注：这一页只交代分工，不讲结果；重点是让听众记住"加噪之前那个数，是 LLM 想出来的"。

## 第 5 页 问题的提出：ε 的承诺依赖三个条件，第三个条件没有保证
- C1 只有 RR 边、带噪度数、加噪计数离开节点（代码保证，✓）。
- C2 被加噪的计数由灵敏度 ≤ GS 的固定函数产生（✗：c_i 由 LLM 产生）。
- C3 每个量只发布一次（代码保证，✓）。
- GS 是针对规则函数 f 推导的上界：degree 为 1、3-star 为 C(D−1, 2)、triangle 为 d̂max − 1；但被加噪的是 L(x)，DP 需要 |L(x) − L(x′)| ≤ GS，而 LLM 没有这个性质。
- 研究意义（四行）：
  - 理论：回答"LLM agent 承担 DP 流水线中的计算时，DP 在什么条件下仍然成立"。
  - 方法：把 LLM 的角色从"执行私有计算"转为"设计可检查灵敏度的程序"，让保证与 LLM 是否算对解耦。
  - 实践：给出精度—隐私—成本的取舍与节点本地模型部署方案。
  - 评估：把机制误差与执行误差分开度量。
- 版式：三条条件竖排，C1、C3 打勾（灰），C2 打问号（橙色）；右侧时间轴式列出四条意义。

# 板块 2　国内外研究现状与研究缺口（P6–P11）

## 第 6 页 方向一：LLM 图推理——准确率是瓶颈，隐私尚未进入视野
- 代表工作：NLGraph（Wang et al. 2023）、图的文本编码（Fatemi et al. 2023）、GraphWiz（Chen et al. 2024）、GraphArena（Tang et al. 2025）；多智能体分解（Hu et al. 2024）。
- 做到哪：把图任务拆到节点级可以提升规模与准确率；子结构计数（三角形、k-star）仍是薄弱环节（Nguyen & Yan 2024）。
- 卡在哪：只优化"算得准"，不涉及"数据是否敏感"；多智能体分解只做"任务拆分"，不做"信任边界划分"。
- 前期观察（放在下方小字）：集中式输入下 LLM 有两类典型失误——写一段程序后自称"运行结果是 X"（X 为编造）、系统性少列度数。
- 备注：这一支把 LLM 当"更强的计算器"，没有考虑执行者本身不可靠、数据不可外发这两个约束。

## 第 7 页 方向二：edge LDP 图统计机制成熟，但前提是"本地计算由确定性代码完成"
- 基础机制：随机响应（Warner 1965）、LDP（Kasiviswanathan et al. 2011）、去中心化社交图合成（Qin et al. 2017）。
- k-star 与三角形：两轮交互三角形计数与度数投影 k-star（Imola et al. 2021）；降通信（2022a）、shuffle 模型下三角形与 4-cycle（2022b）、三角形下界（Eden et al. 2023）、鲁棒三角形（He et al. 2025）、LF-GDPR（Ye et al. 2020）。
- 其他图问题：k-core（Dhulipala et al. 2022）、truss（Zhang et al. 2025）。
- 共同前提（强调色）：**灵敏度直接对"那段确定性代码"推导**；执行者是代码，所以 f 与 L 是同一个东西。
- 备注：这一支的 DP 定理很硬，但定理的对象是代码；一旦把代码换成 LLM，定理的前提就悬空了。

## 第 8 页 方向三：DP 审计与灵敏度验证——方法成熟，对象不同
- 黑盒检测 DP 违规：Ding et al. 2018（统计假设检验）、DP-Finder（Bichsel et al. 2018）。
- 机器学习中的审计：Jagielski et al. 2020、Nasr et al. 2021 用构造的相邻输入 + Clopper–Pearson 区间给出 ε 的经验下界；Steinke et al. 2023 单次训练审计。
- 静态保证灵敏度：Fuzz（Reed & Pierce 2010）、LightDP（Zhang & Kifer 2017）、Duet（Near et al. 2019）、Elastic Sensitivity（Johnson et al. 2018）。
- 共同前提：被审计 / 被验证的对象是**训练算法或人写的程序**，且相邻输入由审计者按代码语义构造。
- 备注："被加噪量必须满足灵敏度"是 DP 系统的基本要求，方法和工具都有；缺的是把它们对准"LLM 执行者"这个新对象。

## 第 9 页 对比归纳：五条研究线，隐私保证的依据各不相同
- 表格（四列：研究线 / 代表工作 / 谁来执行本地计算 / LLM 出错时保证是否成立）：

| 研究线 | 代表工作 | 本地计算的执行者 | LLM 出错时保证是否成立 |
|---|---|---|---|
| LLM 图推理 | NLGraph、GraphWiz、GraphArena、多智能体分解 | 无 DP 环节 | 不涉及 |
| edge LDP 图统计 | Imola 2021/2022a/2022b、Eden 2023、He 2025、LF-GDPR、k-core、truss | 确定性代码 | 成立（f 即代码） |
| LLM + edge LDP（PSC） | Zhang et al. 2026 | 节点 LLM + curator LLM | 不成立：假设 L = f，无审计、无绑定 |
| DP 审计 | Ding 2018、DP-Finder、Jagielski 2020、Nasr 2021、Steinke 2023 | 训练算法 / 代码 | 方法可迁移，对象未覆盖 |
| DP 语言与验证 | Fuzz、LightDP、Duet、Elastic Sensitivity | 人写程序 | 成立，但要求人先写出程序 |

- 一句话归纳（强调色）：**四条成熟研究线各自都成立，交叉处恰好是空白：用 LLM 承担 DP 流水线中的计算，同时要求保证不依赖 LLM 的正确性。**
- 备注：这一页是"别人做到哪"的收口，用一张表把看似无关的四支文献排到同一条轴上。

## 第 10 页 缺口分类：理论缺口、方法缺口、数据缺口
- 三栏卡片，每栏 2–3 条，每条后标证据位置。
- 理论缺口：
  - C2 在"执行者是非确定性黑箱、且其输出与私有输入相关"时失效；现有 ε-edge LDP 定理均假设 f 为确定性函数。
  - 缺"执行者引入的灵敏度"的形式化，以及它与 GS 的可比关系。
  - 证据：原论文 `Theorem 2` 仅以"由顺序组合定理"一句完成证明，默认 L = f。
- 方法缺口：
  - 无绑定：curator 不可信，却决定节点在私有数据上执行什么函数；GS 由隐私控制器另行决定，二者无强制一致。复现代码仅在任务 ID 不一致时打 warning（`framework.py:172`）。
  - 输入未受信：GS 推导隐含"每个噪声邻居恰好一条消息、Sender_ID 真实、列表等于 G′ 对应行"，节点不校验。
  - 无工具：没有面向 LLM 执行者的相邻输入构造与审计器；LLM 生成程序的灵敏度也无验证闭环。
- 数据缺口：
  - 没有"模型 × 图 × 任务 × 错误类型"的审计基准，无法比较不同执行方式的隐私风险。
  - 现有精度指标反映不了隐私：错误可能让误差变小（噪声图上子结构本就偏多），越界反而"更好看"。
- 底部一句：三个缺口对应三个动作——**测不出、管不住、换不掉**。
- 备注：分类是为了让后面的研究内容与创新点一一对上，不要在这一页补充新的文献。

## 第 11 页 关键科学问题：三个 KSQ 对应三个缺口
- KSQ1（对应理论缺口）：当 DP 流水线中被加噪的量由随机、且与私有输入相关的黑箱产生时，ε-edge LDP 在什么条件下仍然成立？如何用可测的下界刻画其失效程度？
- KSQ2（对应方法缺口）：在 curator 与节点收到的消息都不可信的设定下，如何让"执行函数—投影方式—GS—噪声尺度"在节点侧形成不可绕过的绑定，使 LDP 的保证责任回到用户侧？
- KSQ3（对应方法缺口）：能否把 LLM 的作用限制在"设计"，由可验证的程序承担"执行"，从而在保证 DP 的同时保留 LLM 扩展新任务的能力？
- 右侧箭头映射到研究问题：KSQ1 → RQ1/RQ2；KSQ2 → RQ3 前半；KSQ3 → RQ3 后半 / RQ4。

# 板块 3　研究目标、研究内容与创新点（P12–P16）

## 第 12 页 总目标：在不改 DP 机制的前提下，把保证从"靠 LLM 算对"变成"不依赖 LLM 算对"
- 限定条件（强调色）：不修改 DP 机制——RR、Laplace、图投影、ε 拆分一律不动；三类智能体的分工也不动，只改"本地计数由谁、以什么方式产生"，以及"哪些前提必须被验证"。
- 四个模块（画成 2×2 或横向四块，每块一行输入→输出）：
  - 模块① 度量：把执行偏差变成可测的隐私量（对应 KSQ1，输出 ε_emp 下界与越界率）。
  - 模块② 约束：把执行函数与 GS 绑定在节点侧，并强校验消息（对应 KSQ2，输出可构造性证明的节点执行层）。
  - 模块③ 解耦：LLM 设计程序 + 系统证伪/验证 + 运行时兜底（对应 KSQ3，输出与 LLM 正确性无关的执行方式）。
  - 模块④ 评估：精度—隐私—成本消融、token 统计、大图扩展、复合查询（对应 RQ4，输出取舍曲线）。
- 四个研究问题 RQ1–RQ4 以竖排小色块放在右侧，与模块连线。
- 备注：四个模块不是四件并列的事，而是一条链：先能测，才能证明缺口；先能约束，才能把责任收回；最后才能解耦。

## 第 13 页 模块①：三件套把"LLM 会算错"变成"ε 实测下界"
- 口径：误差拆成机制误差（GT-Naive / GT-PSC，与模型无关）与执行误差（同一批噪声下 LLM 与 GT 之差）；报告执行正确率、执行偏差、以及执行误差使总误差变大 / 变小的分量。
- 构造相邻输入：只翻转私有邻居表 P 的一位，消息与公开参数保持不变；3-star 需处理投影耦合（|P| = D 时的替换）；所有相邻对用 Δf ≤ GS 的断言自检。
- 选取策略：S1 随机（估平均越界率）；S2 规则变化最大（选使 Δf 接近 GS 的翻转）；S3 错误诱导（发送者算作共同邻居、误采纳非邻居消息、长列表中间漏数）；S4 边界情形（3-star 的 d = 2 / 3、|P| = D、degree 的长列表）。S1 与 S2–S4 分开报告。
- 统计：稳健越界（重复输出一致且 Δ_LLM > GS）时 ε_emp = ε3·Δ_LLM/GS 作为下界；不一致时追加采样，用 Clopper–Pearson 区间，只有 ε_lb > ε3 才计为越界；总 ε 的实测下界为 ε1 + ε2 + ε_emp。
- 注意（小字）：温度 0 也不确定（P1 中 node 3 三次回答为 4、3.5、4），所以必须重复采样，不能单次判定。
- 版式：左侧"口径—构造—统计"三步流程，右侧一个小示意（一行两列：x 与 x′ 的邻居表只差一条边，对应上报值分布）。
- 备注：这一页要讲清"为什么审计在 DP 上是合法的"——审计只用已发布值和公开参数，属于后处理，不额外消耗预算。

## 第 14 页 模块②：把执行函数与 GS 一起钉在节点侧（对应断裂点②③，正文 3.3 内容三）
- 断裂点② 构造算例（标"构造算例"）：控制器选 triangle（GS = d̂max − 1，只投影 G′），若 curator 改选 3-star、节点在未截断的真实邻居表上算 C(d,3)，CU 上 Δ = 21 > 15；PM 上 Δ = C(236, 2) = 27730 而 GS 约为 240，ε3 实际约为 90。在已有的 5483 次历史运行中没有触发，但复现代码不拦截，只打 warning。
- 断裂点③ 构造算例（标"构造算例"）：伪造 k 条 `Sender_ID` 相同、列表为全部节点的消息，Δ ≈ k·½·|N(i)|，CU 上 k = 100 时 Δ ≈ 400，ε3 实际约为 21；恶意 update 规则（对 j < 10 的邻居加 1000·2^j）一次运行即可恢复与 0–9 号节点的全部边（噪声 > 500 的概率 2.6×10⁻¹²）。
- 三个约束（本模块的产出）：
  1. 三元绑定：任务 ID → 本地函数、投影方式、GS 公式作为一个整体下发；GS 由节点用公开 d̂max 自行计算；不一致时拒绝执行（取代 warning）。
  2. 消息强校验：发送者必须 ∈ N′(i)、每个发送者只保留一条、列表必须等于 G′(发送者)、Sender_ID 与通道身份绑定；私有数据所在的 prompt 只允许结构化字段，禁止自由文本进入。
  3. 证书式下发：curator 只能下发"程序 + GS 声明 + 预算记账"，节点验证通过后执行；不通过则退回或降级为库内任务。
- 一句结论（强调色）：**LDP 要求用户侧自己保证机制合格；既然 curator 不可信，绑定点就必须在节点侧。**
- 备注：这一页是新增内容，也是最容易被质疑"是否属于 DP 研究"的地方，回答是：它决定 LDP 的威胁模型能否自洽。

## 第 15 页 模块③④：LLM 提出、系统证伪与验证、节点执行
- 横向流程：任务描述 + 公开信息（G′、d̂max）→ curator LLM 写受限 DSL 程序 → 证伪器（小图穷举 + 随机/对抗搜索）→ 静态推导灵敏度（通过则继续，过松则退回 LLM 改写）→ 节点本地确定性执行 → 加 Laplace 上报。
- 四层分工（表格，两列：层 / 能保证什么）：

| 层 | 内容 | 能保证什么 |
|---|---|---|
| L1 LLM 提出 | DSL 程序、GS 声明、预算分配 | 无 |
| L2 证伪器 | 小图穷举 + 随机/对抗搜索 | 只能证伪（14 秒内找出"k-star 不截断""非对称投影"两处漏洞） |
| L3 可靠验证 | DSL 灵敏度推导（借鉴 Fuzz / LightDP），或 CheckDP / Duet / SampCert | 证明成立 |
| L4 运行时兜底 | 逐位裁剪贡献；噪声采样与预算记账全部由代码完成 | 构造上成立 |

- DSL 原语：私有邻居集 P、公开带噪图 G′、公开阈值 D、集合交、计数、截断、组合数。
- 模块④：send 消息改由代码生成（约占输出 token 的 23%）；缓存只依赖公开信息的设计步骤；禁止多节点合批、禁止按私有信息路由模型（旁路泄露）；大图（>1000 节点）节点采样扩展；复合查询与预算复用（如带噪度数供 degree 与 3-star 共用）。
- 库外任务：k ≥ 4 的 k-star、路径 / wedge 类计数等，用来检验"LLM 设计程序"是否真有价值。
- 备注：这一页的方法论要点是"让 LLM 提出、不让 LLM 认定"——GS 数值、噪声采样、隐私记账、最终检查都不交给 LLM。

## 第 16 页 创新点三条，逐条对应到内容
- 创新点 1（对应模块①，问题与度量）：把"LLM 作为 DP 执行者"的保证缺口拆成理论、架构、输入三处断裂，给出面向该场景的相邻输入构造、定向错误诱导与 ε 下界审计方法，首次量化其实测隐私损失。

- 创新点 3（对应模块③④，可验证执行）：提出"LLM 提出 + 证伪器 + 灵敏度推导 + 运行时兜底"的可验证程序化执行，使 DP 保证与 LLM 是否正确无关，同时把 LLM 的价值转移到库外任务扩展。

- 底部一句：**从"相信 LLM 算对"到"不依赖 LLM 算对"。**

# 板块 4　技术路线与实验方案（P17–P21）

## 第 17 页 研究方法：形式化—构造—验证—实验 四条方法线
- 形式化：把发布机制写成 M(x) = L(x) + Lap(GS/ε3)，定义"执行者引入的灵敏度" Δ_LLM 与 ε_emp = ε3·Δ_LLM/GS。
- 构造：相邻输入只翻转一位；对每个任务实现相邻操作并断言 Δf ≤ GS（单元测试覆盖）。
- 验证：小图穷举证伪 + DSL 灵敏度静态推导 + 运行时截断兜底；三层由弱到强。
- 实验：同一批噪声上配对比较（基线、改进一、改进二），把机制误差与执行误差分离。
- 版式：四列卡片，每列"方法 / 输入 / 产出 / 失败时的退路"。
- 备注：四条线对应"能不能说清、能不能测到、能不能证明、能不能比较"，缺一条就会被评审追问。

## 第 18 页 技术路线图：诊断 → 约束 → 解耦 → 评估 → 扩展
- 纵向五段流程（每段标"输入 / 方法 / 输出 / 失败则"）：
  1. 平台（已完成）：AgentScope 1.0 实验平台，Naive / PSC / GT-Naive / GT-PSC。
  2. 诊断（模块①）：评估口径 + 灵敏度审计 + 错误分类 → 输出：缺口的存在性与严重程度。
  3. 约束（模块②）：三元绑定 + 消息强校验 + 证书式下发 → 输出：curator 与消息不可信时仍成立的节点执行层。
