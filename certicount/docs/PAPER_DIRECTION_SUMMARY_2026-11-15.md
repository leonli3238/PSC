# CertiCount 论文补充内容与实验路线摘要

日期：2026-11-15

完整论证、代码位置、证据表和文献说明见
[`PAPER_DIRECTION_ANALYSIS_2026-11-15.md`](./PAPER_DIRECTION_ANALYSIS_2026-11-15.md)。
本文是执行摘要，不表示已经完成新的算法、模型调用或 DP 实验。

## 1. 核心判断

对 degree、k-star、triangle 等预先确定的任务，如果 CertiCount 与人工代码使用相同估计量、
相同预算、相同投影和相同噪声分布，那么 agent 执行与普通代码执行的统计结果应当一致。
把执行角色称为 agent，不会额外产生信息或隐私保证。

当前实现也基本符合这一点：curator LLM 生成受限 DP 程序，节点由确定性解释器执行，节点 LLM
调用为零。agent 的潜在价值只剩下程序设计和交互，不应成为默认创新点。

论文需要分别回答两类问题：

1. **执行价值**：确定程序能否按分析语义执行，并满足约定的发布隐私边界。
2. **设计价值**：面对未预先编写实现的任务，自动化能否减少专家工作、提高合格程序产出率，
   或在相同搜索预算下找到更有效的估计量。

推荐主线：

> **面向受限开放图查询的 LDP 程序合成，重点验证随机化输入经过组合、投影和聚合后的统计语义，
> 并由可信执行内核承担隐私保证。LLM 是待评价的程序生成器，agent 数量由消融实验决定。**

候选题目：

> CertiCount: LLM-Assisted Synthesis of Privacy-Certified Graph Queries with
> Noise-Aware Statistical Validation

`privacy-certified` 必须有健全性定理和明确的相邻关系支撑；统计部分只有在证据足够时才能使用
validation 或 guarantee。

## 2. 当前证据与缺口

| 当前资产 | 能支持的结论 | 不能直接推出的结论 |
|---|---|---|
| 受限 DSL、解释器和 GS 推导 | 已有可执行的图 DP 分析原型 | 任意自然语言查询都能正确处理 |
| curator 生成、检查和反馈 | 存在工具反馈闭环 | 闭环优于模板、搜索或同预算重采样 |
| 确定性节点执行 | 数数过程不依赖节点 LLM | 多 agent 协同带来了统计精度增益 |
| PM degree 100 次噪声重复 | PM 与同噪声 GT-DSL、GT-PSC 一致 | 有 100 个独立成功设计，或优于专家代码 |
| A3 真实设计实验 | 70 次设计、61 次接受、119 次 LLM 调用 | 接受的程序都有可用统计效用 |
| 证伪和历史 fuzz | 有反例搜寻与回归证据 | 有限测试证明了所有程序 GS 正确 |
| Qwen 节点审计 | 某些配置存在显著隐私越界 | 所有模型、节点和配置都越界 |
| 复合查询账本 | 已有批内共享发布和预算组合 | 已有跨会话、恢复和多轮可信记账 |

必须区分：

- **噪声重复**：同一程序的重复执行，用于估计误差分布。
- **设计重复**：LLM 独立生成多个程序，用于评价自动化的成功率和稳定性。

A2 的 100 次 degree 运行只有一个生成设计；多次噪声执行不能替代多次独立设计。

### 最有研究价值的现象

A3 的 61 个接受程序中有 9 个只使用公开含噪邻表 `N(...)`，完全没有读取私有邻表 `P`。例如：

```python
return comb(size(N(self)), 4)
aggregate: total
```

该程序第三阶段 GS 为 0，但 PM 平均相对误差为 **30.0813**，对应 GT-DSL 为 **0.1531**。
另一个基于含噪邻表的三角形程序，平均相对误差为 **100.9365**。这些数值按真值归一化，
不是相对基线的倍数。

第三阶段 GS=0 不表示整个流程没有隐私成本。固定合法发布的随机化邻表后再计算可以属于后处理，
此前对邻表的局部随机化仍有预算；真正失效的是估计量把随机化输入当成真实图。

现有无噪声测试把公开行设为真实图，即 `N(self) = P`。它可以发现计数因子错误，却无法区分
真实邻表与 RR 邻表的统计性质。由此可形成核心研究问题：

> **如何验证一段对原始数据成立的计算，经过随机化发布、投影、聚合和共享随机量复用后，
> 仍然是一个可用的统计估计器？**

只加入“禁止 N(self)”或“误差不能高于参考程序”的过滤规则可以修复当前案例，但方法贡献较弱。
更有价值的是跟踪数据来源、随机量依赖、偏差/方差和发布依赖，并能针对具体的组合错误给出
反例和重写反馈。

## 3. 推荐的论文贡献

正文应形成一条完整证据链，而不是并列堆叠多个模块。

### C1：查询规格与估计程序分离

建立受限查询 IR，描述目标图模式、公开筛选、计数约定、归一化方式和误差要求。自然语言只负责
得到 IR，估计器再从 IR 生成。这样可以分别测量语言理解、估计器设计、隐私证明和执行错误。

不支持的规格必须拒绝。当前 `task=None` 会跳过语义检查，因此不能把“GS 推导通过”解释为
“回答了任意未知任务”。

### C2：隐私分析与统计分析独立

隐私模块回答“需要多少预算”；统计模块回答“发布结果估计什么，偏差和方差来自哪里”。
状态至少应区分：

`语法合法 -> 规格匹配 -> 隐私条件满足 -> 统计验证通过 -> 已发布`

不应使用一个含糊的 accepted 标签覆盖不同性质。

### C3：随机化输入的组合语义

为有限表达式族记录：

- 数据来源：原始私有量、RR 发布量、带噪度、后处理量、已发布估计量。
- 隐私状态：敏感度、预算、相邻关系、发布依赖。
- 统计状态：期望或偏差界、方差界、协方差和随机量复用关系。

对未校正 RR 计数、非线性组合、投影和共享发布给出可定位诊断。均值校正和独立边乘积属于已有
知识，新增价值必须体现为组合分析、证明覆盖或相对简单模拟过滤器的额外效果。

### C4：收敛的可信计算基

当前证书核验再次调用同一个 `derive`，可以阻止 curator 低报 GS，但不能独立发现推导器自身
错误。应给出受限 DSL 健全性证明，并让结构化证书由小型 checker 按规则核验。

还需说明图规模等公开参数由可信机制生成或验证、解释器遵循被证明的语义、预算检查先于发布，
且拒绝、异常、日志和反馈也满足约定的隐私边界。代码行数少有利于审查，但不能替代证明。

### C5：可测的自动化增益

不能默认 LLM 或 agent 优于普通代码。应测量未见结构、组合关系和反馈修复上的增量，并把收益
拆分为语言理解、程序生成、工具反馈、统计诊断和执行隔离。

如果模板或编译器已经覆盖全部任务，应转向图 DP 验证、编译或审计，而不是人为削弱模板以维持
agent 叙事。

## 4. 必须加入的基线

1. 相同机制和预算下的专家静态程序。
2. 任意 k 的参数化 k-star、degree moments 和组合模板库。
3. 自然语言解析后调用已认证 DP 库的语义路由。
4. 在相同 DSL、检查器和评分器下的枚举、随机或约束搜索。
5. 单次 LLM 生成后直接检查。
6. 与反馈闭环总 token、检查次数或时间匹配的独立重采样。
7. 当前 CertiCount 的 exact 和 search 路径。
8. GT-PSC、GT-DSL 和可信代码守卫。
9. 共同支持子集上的 DPGen、CheckDP 等方法。

GT-PSC 和 GT-DSL 只要使用事先给定的参考代码，而不是测试集真值或最优参数 oracle，就是合理
且必须保留的代码基线。不能因为名称含 GT 就排除它们。

成本需要报告候选检查次数、总 token、总 CPU/GPU 时间、墙钟时间、峰值内存和人工介入次数。

## 5. 泛化基准

当前“库外”主要是相对 PSC 旧任务表而言。4-star 和 5-star 还是同一 `kstar_source(k)` 的参数
变化，不足以证明结构泛化。正式基准应区分：

- 参数和自然语言表述泛化。
- 多项式、线性组合和归一化。
- 已知原语的新组合。
- 公开条件或公开属性上的新查询。
- 新的小图模式。
- 复用已发布统计量的多轮工作负载。
- 不支持或有歧义、应被拒绝的规格。

建议先做 20-30 个小型 pilot 规格，正式研究扩到约 40-60 个规格、至少 4-6 个结构或组合家族。
训练示例、工具示例、调参任务和测试任务按结构家族隔离。

评测至少包括：

- 正确 IR 和自然语言两条输入路径。
- ER/BA 开发图，以及 SBM、几何图、极端 hub 图和真实图等留出分布。
- 多个 epsilon 点，例如 `{0.5, 1, 2, 4}`。
- 拒绝、失败、超预算和无法表达的任务。
- 零或近零真值任务，避免通过省略行规避 RE 分母问题。

## 6. 实验路线

| 编号 | 实验 | 关键产出 | 验收重点 |
|---|---|---|---|
| E0 | 冻结与口径核对 | 主张-证据矩阵、预算表、状态定义、可重跑结果清单 | 核心数值和执行语义可追溯 |
| E1 | “代码就够了”对照 | 专家代码、模板、路由、搜索与 CertiCount 的产出率和成本 | 模板无法覆盖非平凡增益 |
| E2 | 统计失效诊断与修复 | 119 份草稿离线回放、错误族、诊断和修复实验 | 对新错误族和未见分布有效 |
| E3 | 端到端精度与泛化 | 独立新设计、留出任务和图的完整误差表 | 设计重复与噪声重复分开统计 |
| E4 | 理论、证书与验证 | 健全性定理、独立 checker、变异和篡改测试 | 隐私边界闭合，测试不作证明 |
| E5 | 节点隐私审计 | 多模型、多任务、匹配解码参数和强对照 | 发现与确认样本独立，口径明确 |
| E6 | 收益来源消融 | 路由、反馈、统计检查、来源信息、单/多 agent | 匹配预算，保留负结果 |
| E7 | 规模与成本 | 发布、通信、内存、延迟和人工成本 | 分别报告各任务路径的可扩展性 |

### E0：先修正旧口径

优先核对：

- GT-PSC 被写成不可部署参照的问题。
- 把单次执行正确视为 DP 认证的旧指标。
- 11 月 10 日报告的预算拆分；原始记录中 RR 程序是 `(1, 0.2, 0.8)`，参考 k-star
  是 `(0, 0.4, 1.6)`，degree 是 `(0, 0, 2)`。
- README 中“真实设计评估只跑过 mock”的过时描述。
- 已删除 adaptive/pool 模块的历史结果与当前主方法的边界。

### E1/E2：先做低成本判别

E1 在当前任务比较专家代码、模板、路由和 CertiCount；E2 先离线回放现有 119 份草稿，再加入：

- 直接在 RR 假边上做非线性计数。
- 投影过强导致偏差或信息损失。
- 私有量限制过松导致 GS 过大。
- 聚合倍数或归一化错误。
- 相关随机量被误当成独立量。
- 复合估计分母不稳定。

E2 对照为当前无噪声门、完整管线模拟过滤器、来源与统计分析、带定位反例的反馈重写。
指标包括有害程序漏接收率、有效程序误拒率、诊断类别、修复成功率、误差均值和尾部、搜索成本。
应加入正确的公开数据后处理程序作为负对照，避免退化为“见到 N 就拒绝”。

### E3：主实验

保留现有六张图用于历史可比性，再加入结构不同的合成图和更大的真实图。建议：

- 每任务、每模型先做 10 次独立设计的 pilot。
- 关键结论扩到 20-30 次独立设计。
- 每个冻结程序先做 200 次纯代码噪声重复。
- 主表按 Monte Carlo 标准误扩到约 1000 次噪声重复。

报告 MAE、MSE/RMSE、偏差、P90/P95、极端失败率、覆盖率、成本和置信区间。按任务和设计聚类，
事先定义非劣性容差与实用性阈值。若不同程序会错开相同随机序列，应使用按阶段和节点索引的
随机数带，仅设置相同 seed 不够。

### E4/E5：证明与审计

理论部分至少覆盖 DSL 灵敏度健全性、固定公开历史下局部机制保证、完整交互预算组合、可信执行
和数值浮点实现。统计理论可先覆盖少量表达式族，不要求一次覆盖任意查询。

现有 Qwen3-8B PM degree 测试在联合校正下确认 49/158 个实例越界，各集合分别校正时为
51/158；随机参考集为 4/60。不能把筛选或迁移集合的比例写成总体发生率。

后续审计需加入更多模型、任务、图和匹配解码参数，使用独立发现/确认样本并统一多重比较。
审计统计的是 `LLM(x) + noise` 的发布分布，不是两次随机输出的最大差。若原始邻表已经发送给
不可信模型服务，后续加噪不能撤回该次披露。

### E6/E7：消融与成本

消融至少包括无自然语言模型、只做路由、无反馈、同预算重采样、通用提示替代定位反例、
无统计检查、只有端到端模拟、无来源信息和单 agent 对多 agent。

规模实验先选 `n=10^3`、`10^4`；`10^5` 只用于已证明资源可承受的路径。RR 仍可能产生稠密
公开邻接结构，纯代码执行不等于自动可扩展。若“非专家可用”是核心主张，还需要用户研究或
专家干预日志，不能只用 token 少推断易用性。

## 7. 隐私模型与指标

必须明确主定义是节点邻接向量的单比特变化，还是整张无向图的一条边变化。后者会改变两个端点。
当前下三角 RR 与双端点报告结构下的保守关系级组合为：

```text
epsilon_relation = epsilon_1 + 2 * epsilon_2 + 2 * epsilon_3
```

若声称整图 edge-LDP，所有方法都应按这个口径或更紧且已证明的会计重新标定。按节点变化定义也
不等于 node-DP。

建议分别报告：

- 有理论支持的保证范围和假设。
- 程序产出率、支持任务覆盖率和拒绝率。
- 规格错误、隐私失败和统计失败。
- 所有成功发布的误差分布及失败成本。
- 黑盒审计的证伪结果、检验功效和适用配置。

不建议继续使用旧计划的 `CU@epsilon` 主指标。它把单次执行正确混同于 DP，罚值还可能让拒绝
优于诚实发布，掩盖覆盖率问题。

## 8. 分阶段推进

| 阶段 | 工作 | 进入下一阶段的条件 |
|---|---|---|
| P0 冻结核对 | 证据矩阵、预算表、状态定义、历史结果分级 | 核心数值和执行语义可追溯 |
| P1 低成本判别 | 模板、路由、搜索和现有设计记录的离线对照 | 找到模板不能直接覆盖的可研究任务族 |
| P2 技术贡献 | 查询 IR、统计分析、证明和独立 checker | 统计模块有超出简单模拟过滤器的价值 |
| P3 小规模验证 | 少量模型、未见结构任务、匹配预算消融 | 效果可重复且达到事先定义的阈值 |
| P4 主实验与写作 | E3、E5、E6、E7，冻结代码和提示 | 每个论文主张都有保留失败的完整证据 |

建议先安排约两周的 P0/P1 判别。判别问题是：

> 当专家模板、现有认证 DP 库和普通搜索都可用时，CertiCount 还解决了哪个未被解决的问题？

如果这个问题不能写成可被实验否定的假设，继续增加固定任务运行次数不会补足创新性。

## 9. 其他方向

### 多轮可信查询规划

复用已发布统计量、分配剩余预算、分解问题或拒绝查询。该方向更适合 agent 叙事，但难点会转到
发布依赖、相关噪声、查询等价、幂等发布和持久预算账本。当前 `composite.py` 每次新建账本，
只是批内组合起点。

### 图 DP 验证与编译

研究投影、私有集合迭代、随机化邻接行和共享发布下的组合分析、证明、反例与独立核验。它与
现有资产连续；若 LLM 设计收益有限，这条路线比继续强调 agent 更自然。

### 神经预处理 DP 审计

研究神经模型处理私有输入后，系统按预期敏感度加噪时的真实发布行为。现有 Qwen 结果是起点，
但需扩展到多任务、多模型和多种工具策略。还必须与随机、启发式和已有黑盒搜索比较，相邻性
由代码验证，不能由模型自述。

### 新的 LDP 图估计器

选择具体图模式或公开结构约束，推导新的偏差/方差界并实现强基线。理论风险最高，但算法贡献
最清晰。已有 edge clipping、调参或预算网格最优化不应包装成新估计器。

## 10. 最终取舍

| 路线 | 连续性 | 主要审稿风险 |
|---|---|---|
| 查询合成 + 随机化输入统计验证 | 高 | 被视为 DPGen、验证器或 LLM 前端的简单组合 |
| 多轮可信查询规划 | 中 | 简单查询优化器即可覆盖大部分收益 |
| 图 DSL 验证与编译 | 高 | 新规则只是重现已有敏感度公式 |
| 神经预处理 DP 审计 | 高 | 只有个案或已有黑盒审计的普通应用 |
