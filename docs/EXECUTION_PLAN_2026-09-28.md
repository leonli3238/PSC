**阶段一：对齐纯代码机制**

工作包 1.1：冻结起点和建立机制规格。

沿用已有 `source_manifest.json` 与离线诊断，保存当前工作区的完整可复现源码快照。当前存在未提交修改，仅记录 HEAD 不够。快照应包含源码内容、未跟踪的相关源码、依赖版本、数据哈希、论文哈希和参数；排除 `.env`、密钥、缓存及无关文件。

新增 `docs/MECHANISM_SPEC.md`，按任务记录 RR 是否执行、预算、投影对象、敏感度、报告机制、聚合和截断。每项给出来源页码，并标注“论文明确”“论文矛盾”“项目补充”“诊断候选”。以下是当前行为，不是尚未核实的作者实现：

| 任务 | ε=2 时预算 ε1/ε2/ε3 | 原始局部计数 | 当前 GS | 聚合 |
|---|---|---|---|---|
| degree | 0/0/2 | d_i | 1 | sum/n，最后截断到非负 |
| 2-star | 0/0.4/1.6 | C(min(d_i,D),2) | D | sum，最后截断到非负 |
| 3-star | 0/0.4/1.6 | C(min(d_i,D),3) | C(D,2) | sum，最后截断到非负 |
| triangle | 1/0.2/0.8 | 在真实邻居和投影后的噪声消息上按规则计数 | max(1,D−1) | sum/3，最后截断到非负 |

D 是当前 noisy max degree 向上取整后的阈值。明确论文附录 triangle 示例的 0.5/1 矛盾及正文/附录 GS 写法差异。核实作者公开代码和补充材料；若未找到，保留差异清单，不把选定解释表述为作者已确认。技术推导只使用原文、作者代码和其引用的原始论文；不给未经核实的经验选择“论文规定”的标签。

修改 `psc/ground_truth.py` 的 RunTrace 和 `psc/dp.py` 的可选 trace 输出，新增 `scripts/audit_mechanism.py`。默认执行路径保持既有行为；trace 不额外消耗随机数。必须记录：

- 原图 n/m、度向量、最大度、四任务真值与数据哈希。
- ε1/ε2/ε3、各节点 noisy degree、取整前后 D、GS、实际 Laplace scale。
- RR 后图、投影后图及其哈希；必要时保存规范化边列表。
- 处理节点的顺序、随机保留的邻居、各节点度变化、删边总数。
- 原始/投影后本地计数、加噪前总计数、逐节点噪声、加噪后报告。

工作包 1.3：先查 k-star。

按以下顺序逐项判断，每次只改变一个机制因素：

| 顺序 | 检验 | 方法与预期产物 |
|---|---|---|
| K1 | 计数正确性 | 从度向量独立算 C(d_i,k)；验证裁剪后恰为 C(min(d_i,D),k) |
| K2 | 预算解释 | 核实缺省阶段为 0 后的分配；从推导到实际日志核对 ε3，无预算丢失或重复消耗 |
| K3 | 敏感度定义 | 固定公开阈值 D，推导理想函数的单比特差分；将数学紧界、论文上界和项目当前实现分别列出 |
| K4 | 噪声实现 | 在固定 D 下验证每节点均值 0、方差 2(GS/ε3)^2，聚合方差与独立采样一致 |
| K5 | D 的分布 | 统计 D−d_max、裁剪比例、无效物理上界、ceil/floor 的配对差异 |
| K6 | 最终截断 | 统计截断前有符号偏差、方差、负值比例和截断后 RE |

固定 D、只依赖裁剪度数的理想 k-star 函数，可以通过组合数差分推导更紧界；这只能作为独立数学检查。若其与论文使用的 C(D,k−1) 不同，不能直接把更紧界替换为“忠实复现”，必须单独标注机制改动并检查完整组合条件。

复用已有 ceil/floor 诊断，避免再次把已不足以解释差距的因素当首要方向。只有出现新机制假设或代码修复才重跑对应对照。

工作包 1.4：再查 EE triangle。

使用同一原图、同一 RR 抽样、同一 noisy degree 和同一标准 Laplace 向量，记录五个输出：

1. 原图精确 triangle 数 T。
2. 使用未投影噪声图、但仍按 PSC 的真实邻居/update 规则计算的 Y_RR。它不是简单数噪声图里的全部三角形。
3. 投影后按相同规则计算的 Y_proj。
4. 加 Laplace 后、截断前的 Y_noise。
5. 最终 Y_final=max(0,Y_noise)。

逐次验证有符号恒等式：Y_final−T=(Y_RR−T)+(Y_proj−Y_RR)+(Y_noise−Y_proj)+(Y_final−Y_noise)。相对误差含绝对值，不能把各阶段 RE 直接相加。

先比较当前随机节点顺序与固定节点顺序的对称投影；必要时再实现“同时保留选择的交集”等有明确定义的无向有界投影候选。不同候选共享事先定义的随机优先级用于配对，每个候选必须保持其宣称的边缘分布。投影顺序或算法改变时，不能只复用随机种子就声称逐步使用了相同随机数。

不投影和仅单边裁剪可用于定位误差，但若未满足当前 GS 的前提，只标为离线反事实诊断。不得因为误差更低就并入满足同一隐私参数的正式比较。

新增小图独立检查：枚举足够小的原始邻居配置，在固定噪声消息图下逐比特改变真实邻居，检查理论局部计数差分；对更大图抽样补充。单元测试发现反例有价值，但通过有限样本不能代替形式化证明。

工作包 1.5：实验矩阵和归因。

| 轮次 | 范围 | 重复数 | 用途 |
|---|---|---:|---|
| 开发诊断 | CU/Do 的 2-star、3-star，以及 EE triangle | 每格先 1000 | 定位最主要因素，保存逐阶段分布 |
| 重点确认 | 仍存在差距的任务与候选 | 每格预定总数 5000 | 分析均值、标准误、分位数、配对差异 |

大量运行只保存紧凑逐次统计；全量中间图用于固定诊断样本和异常样本，避免 PM 图重复落盘造成不必要开销。均值和标准误以独立的整次运行计算，不把同一运行的多个节点当独立实验。

输出 `results/alignment/<experiment_id>/` 下的 `manifest.json`、`runs.jsonl`、`stage_summary.csv`、`hypotheses.csv`，以及 `docs/ALIGNMENT_FINDINGS.md`。每项假设必须得到“证实、排除、证据不足”之一，记录效应大小、实现与来源。

阶段一完成标准：独立计数与预算检查通过，确认的错误已修复，重点差距能够定位到阶段和参数；无法核实的作者细节有清楚范围。不能设定“必须落入论文均值的 5% 才通过”之类拟合目标。论文通常缺少方差，论文点值未落入本地置信区间也不自动构成统计显著差异。若无法完成严格对齐，可以进入阶段二完善工具；后续主实验必须标为“按公开描述实现”，暂不宣称严格数值复现。

**阶段二：建立可回放评估**

工作包 2.1：把实验随机性显式化。

新增 `psc/randomness.py`、`psc/trace.py`。第一阶段已有 trace 扩展为以下记录：

| 对象 | 必需内容 |
|---|---|
| experiment_id | 不可覆盖的实验标识、代码快照、参数和数据版本 |
| run_id | 数据集、任务、方法、ε、重复序号、模型配置和实验版本 |
| noise_id | 配对样本标识与各阶段基础随机量哈希 |
| NoiseTape | 按规范边顺序存的 RR uniforms、度噪声标准 Laplace 向量、投影随机优先级、报告标准 Laplace 向量 |
| mechanism_id | 预算、GS、取整、投影、聚合和截断规则的版本 |
| llm_replicate | 固定噪声下的模型重复调用序号，与 DP 重复序号分开 |

使用独立阶段子流，稳定哈希或显式编码生成种子，不用 Python 内置 hash()。不同数据集/任务默认使用不同子流；需要做模型对照或方法配对时，通过明确的 pairing_group 共享基础随机量。

这里必须区分：同机制的 GT/agent 可以重用同一噪声图和实际噪声；不同 ε 或 GS 的方法可以共享 uniforms 和标准 Laplace Z，再分别按各自机制变换。不能给 ε1 不同的 Naive 和 PSC 强行使用同一张已经扰动好的图。历史结果保留原始 RNG 版本，新系统引入新版本，不能把随机流变更后的结果当成历史修复前后配对。

工作包 2.2：记录全部调用结果。

扩展 `psc/models.py`、`psc/events.py`、各 Agent 调用入口。每次逻辑调用有稳定 call_id，每次网络尝试有 attempt_id；记录 agent/阶段/节点/输入哈希/完整实际 prompt/原始回复/解析结果/校验结果/异常原因/重试/耗时/模型实际标识。

usage、finish_reason、供应商 request_id 等仅在接口返回且适配器可获得时记录，缺失写 null 并标记来源，不能伪造。usage 采集在阶段二完成，阶段四据此做成本分析。日志中不包含凭据；真实邻居、未加噪计数及包含它们的 prompt 只保存在可信审计存储。公开结果仅提供适当汇总与引用，不直接打包私有 trace。

当前聚合 prompt 把数值格式化到小数点后四位。评估必须同时保存原始报告和实际显示数值，增加 `aggregate_reference_displayed` 与 `aggregate_reference_full_precision`，将输入舍入差异与模型算术误差分开。任何改变显示精度的行为都需要 prompt 版本号。

工作包 2.3：统一解析与失败语义。

新增 `psc/parsing.py`，替换散落的宽松逻辑：

- 接受完整结果 JSON、完整单个数值文本，或明确的最终答案标记。拒绝任意正文中的最后一个数字。
- 拒绝 bool、NaN、Inf、数字溢出及字段类型不匹配。保留原文与具体失败原因。
- send 核验 Sender_ID 与调用节点一致、编号范围有效、列表格式明确。格式规范化与语义改写分开记录，不能悄悄改成正确邻居集合。
- degree/k-star 的局部计数应为非负整数，triangle 局部计数应符合规则允许的半整数；无效输出记录语义失败。符合类型但计算错误的值保留为模型错误，不能用 GT 自动替换。
- curator/controller 任务不一致时标记该次无效，不继续采用不匹配的 DP 参数。
- 任务识别代码回退若保留，记录原始识别结果与回退后结果，并与无回退实验分别命名。

固定三类状态：调用可用但模型算错；协议/解析失败；框架执行失败。保留合法零估计与失败后零兜底的差别。若采用现有 send 丢弃、update 保持初值或 aggregate 返回零的容错策略，作为明示的 pipeline policy 记录并计入端到端结果；严格终止模式则报告缺失，不把缺失当正确零。

模型答错、格式失败不得通过反复重跑选出成功答案。基础设施的可重试错误按预先固定策略恢复，并保留全部尝试。不能丢弃失败后只选 10 次成功运行来构造主表。

工作包 2.4：改造执行器与持久化。

改动 `psc/experiments.py` 和 CLI：每完成一次运行就追加终态结果与索引，原子更新 checkpoint，summary 由已有记录重建；失败不会丢掉其他已完成结果。新增待实现能力：`--experiment-file`、`--resume`、`--dry-run`、`--methods`、明确的 run 范围、机制版本和噪声版本选择。

resume 只复用数据、机制、prompt、解析策略、模型配置均一致的完整结果；配置变更应创建新的实验。中断中的单次运行可以使用固定 tape 从头再跑，但必须记录新增调用成本；若要复用已完成调用，则需要精确输入哈希和调用状态。不能承诺远端请求层面 exactly-once。

工作包 2.5：拆分指标。

设 a 为 LLM 最终估计，b 为相同机制和噪声下的规则估计，d=max(truth,0.001n)。各指标分别解释：

| 指标 | 定义/用途 |
|---|---|
| RE_LLM | mean(abs(a−truth)/d)，最终统计效果 |
| RE_paired_rule | mean(abs(b−truth)/d)，该批样本的机制效果 |
| delta_mean_RE | abs(mean(RE_LLM_each)−mean(RE_rule_each))，保留旧口径但明确可能抵消 |
| mean_abs_RE_gap | mean(abs(RE_LLM_each−RE_rule_each))，避免跨次正负抵消 |
| mean_normalized_estimate_gap | mean(abs(a−b)/d)，直接度量输出偏离；用于避免真值两侧等 RE 掩盖差异 |
| signed_bias/quantiles/zero_rate | 偏高偏低、长尾与截断情况 |
| node/send/aggregate accuracy | 只用于定位局部推理，不作为独立 DP 重复数 |
| coverage/failure rates | planned/completed/invalid/fallback 各自数量 |
| delta_GT_reference | 与独立 GT 重复均值比较，另标 GT 样本数；不与 paired delta 混淆 |

置信区间按完整运行抽样；模型/方法共享 noise_id 时，对配对差值进行 bootstrap。十次结果区间较不稳定，提供所有逐次值，并把扩大重复数作为预先定义的补充实验，保留原始十次表。

工作包 2.6：验收。

必须验证：固定 tape 的 GT/mock/规则输出逐阶段一致；并发=1/8 时机制和排序一致；改解析器回放同一原始回复得到预期结果；NaN/Inf/正文数字探针被拒绝；中断后恢复不丢数据、不重复纳入统计；汇总可完全由运行记录重建；日志没有凭据。

真实接口预检只验证可用性、角色配置、追踪和失败记录，不能把模型必须高准确率作为筛选样本的条件。正常解析但算错应进入实验结果。只有阶段二确定的实验协议冻结后，才能产生可合并的正式主实验样本。

交付：`scripts/replay_experiment.py`、统一实验配置模板、回归测试、可回放的小型样例，以及 `docs/EVALUATION_PROTOCOL.md`。预计工程量 4–6 人日。

**阶段三：补齐论文主实验**

工作包 3.1：冻结实验协议。

使用单独的论文配置，例如待新增 `configs/paper.toml`，与现有 `hy3-ioa` 配置分开。论文目标设置：node=GPT-4.1-mini、curator=GPT-4.1、temperature=0，ε=2，六图四任务，PSC/Naive 每格 10 次。模型服务实际可用性和返回标识需在执行前验证；若原版本已不可用或别名指向不同快照，记录该事实并将替代结果独立命名。

优先使用可核实的模型快照；论文未给快照日期时，如实记录不确定性。不要把 OpenAI-compatible provider 名称等同于实际使用论文模型。控制器模型、stream、token 上限、超时、重试、并发、prompt/解析版本、回退策略均写入 manifest。

选择 10 个固定 DP 重复编号，模型对照共享同机制的 tape。另用独立 GT 种子库跑至少 1000 次，形成估计机制表现的稳定参考。固定十次主表后，才决定是否按事先规则增加到 30 次，新增结果单列而非替换十次表。

工作包 3.2：预检与正式运行分开。

先在 CU/Do/EE 的代表性调用上预检：node send、node update、curator aggregate、Naive 大 prompt、stream 重试和 usage。预检前后修改配置时，这批调用不计入正式实验。对 PM 先检查当前完整 prompt 能否放入实际模型上下文，不能通过静默截断或更换图表示保留“同条件”标签。

先测 CU/Do 和 EE 的少量正式 run，如果协议保持冻结，可作为十次实验的前几次继续追加；若修改了协议或机制，则开启新实验并保留旧结果。真实模型质量差不是删除样本的理由；接口配置错误、意外截断或日志损坏才是需要修复协议的依据。

工作包 3.3：分批完成 Table 2。

| 批次 | 数据集 | 10 次 PSC+Naive 的逻辑调用数 | 目的 |

Exp3 要拆清楚去掉 GS 优化会同时改变 ε2 和 ε3。主对照遵从论文/当前定义，额外“固定报告预算只改变 GS”的诊断若合法可加，但不能把两者混作单因素实验。
