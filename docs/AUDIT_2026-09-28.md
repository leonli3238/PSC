PSC 当前效果与论文复现差距审计（2026-09-28）

本次审计基于当前工作区代码、最新的 `results/pilot/hy3-ioa_r3_v2/`、此前 pilot、已有 1000 次 GT 结果，以及仓库内原论文 `paper/psc_acl2026.pdf`。正文页码按 PDF 的 1–16 页计。未修改算法、配置或既有实验结果，未调用真实模型 API；新增的是本报告和 `results/audit/2026-09-28/` 下的离线诊断记录。

核心判断：当前项目已完成主要流程和小图上的模型执行验证，但尚不能称为论文实验的完整复现。主要问题是 k-star 的代码机制结果持续偏离论文、triangle 的部分数据集差距被总体均值掩盖、真实实验覆盖不足以及评估口径不完全可比。最新 pilot 中模型算术错误已经很少，继续优先优化节点 prompt 很难消除当前的大部分误差。

**2. 大误差主要从哪里进入**

当前链路是：任务识别 → 预算和灵敏度 → RR 噪声图（triangle）/邻居投影（k-star）→ LLM send/update → 各节点 Laplace 报告 → LLM 聚合 → 非负截断。诊断时需要分开计数机制的偏差、Laplace 方差、模型执行差错和最终截断效应。

CU 的 3-star 真值为 494。最新第 1 次运行的节点原始计数总和正好是 494，说明本地计数无误；但最大度从真实 8 被噪声估为 19。代码因此使用 GS=C(19,2)=171，预算 ε3=1.6，每个节点的 Laplace scale=106.875。49 个节点噪声累加后最终为 2450.198，模型和代码参考一致。三次输出分别为 2450.198、1036.068、0，平均 RE=2.0191。这里的高误差不需要任何 LLM 错误即可产生。

triangle 还叠加了 RR/投影后的计数偏差。CU 最新第 1 次真值 57，规则计数在加 Laplace 前为 92/3=30.6667，聚合噪声贡献约 +242.8013，最终 273.468。Do 第 1 次真值 95，加噪前为 101，聚合噪声约 -134.1971，截断前为 -33.1971，最后输出 0。输出 0 是现有规则的正常结果，不能单独认定为调用失败。

固定灵敏度时，n 个独立 Laplace 报告之和的标准差为 sqrt(2n)×GS/ε3；degree 再除 n，triangle 再除 3，k-star 直接求和。最大度噪声和高阶组合数使小图上的 3-star 特别容易出现大幅波动。对应实现：`psc/dp.py:106`、`psc/library.py:224`、`psc/ground_truth.py:91`、`psc/rules.py:78`。

本次对 CU/Do 各任务追加了 5000 次纯代码运行，使用 `default_rng([9131,i])`。再从每项 RE 样本重采样 50000 组，每组三次，得到三次均值的经验分布（重采样 seed=119）。这仅刻画当前实现的波动，不是论文结果的置信区间。

**3. 与论文存在的持续数值差距**

已有 1000 次代码结果（`results/ground_truth/table2/`）中，GT-Naive 的 24 个单元格与论文相对偏差均不到 1%；六张图的节点数、边数与 Table 1 一致，各任务记录中的真值也与当前图的精确计数一致。这降低了基本数据读取、任务定义、RR 概率整体错误的可能性，但不等于逐条边和所有预处理步骤均获得作者版本验证。

| GT-PSC 任务 | 当前六数据集平均 RE | 论文对应平均 RE | 相对差距 |
|---|---:|---:|---:|
| degree | 0.01181 | 0.01187 | -0.5% |
| 2-star | 0.11419 | 0.06467 | +76.6% |
| 3-star | 0.44732 | 0.36488 | +22.6% |
| triangle | 0.88327 | 0.87375 | +1.1% |

论文平均值这里按六个已发表单元格重算，末位可能与论文表格直接打印的 Avg. 不同。

2-star 在六张图上都高于论文，单项差距约 53%–88%。README 将其描述为“略高”“更保守”不充分。本次用相同最大度噪声和报告噪声做了 10000 次 ceil/floor 配对诊断，仅更改取整规则：CU 的 2-star 为 0.17141→0.15983，Do 为 0.10433→0.09840，仍明显高于论文 0.1062/0.0585；六图改善约 0.04%–6.8%。CU 的投影阈值在该批样本中均不低于真实最大度，所以真实邻居裁剪也无法解释该例差距。结论是：取整不足以解释 2-star 差距，预算解释、实际灵敏度定义、报告噪声与作者实现需要独立对齐。不能为贴表格数字而无依据缩小噪声。

triangle 的总体均值掩盖 EE 的局部偏差：当前 0.4059、论文 0.2803，高 44.8%。本次 EE 再跑 5000 次得到 0.39993，均值标准误约 0.00373；加 Laplace 前平均聚合计数约 609.80，而真值为 889。该差距在新随机流下持续存在，应优先拆分 RR 后计数、投影删边后计数和最终噪声，审查随机顺序对称删边是否与作者实现一致。尚无证据把差距唯一归因于投影。

**4. 原论文自身存在未规定或不一致的细节**

论文第 5 页 Algorithm 2 返回最大度作为灵敏度；第 3 页讨论 triangle 上界为最大度；第 16 页 DP 库示例却写 `degree-1`。项目选择了附录的最大度减一，这是有来源的选择，但不能称为论文各处完全一致。k-star 的真实邻居投影、最大度取整，以及无向图删边的对称性/处理顺序没有得到足够完整的规定。当前实现取 ceil、在 k-star 投影真实邻居，并对 triangle 噪声图按随机节点顺序对称删边。

此外，论文第 16 页 triangle update 示例从 0 开始只加 0.5，却在最终状态写成 1；当前 `library.py:85` 和测试按规则结果写成 0.5。这是合理修正，但 README 的“逐字对应”不准确。degree/k-star 的完整库条目和部分 few-shot 内容也由项目补充。复现报告应分别列出“原文明确要求”“原文不明确的选择”“纠正原文矛盾”，而不能把选择写成作者已经确认的事实。

**5. Agent 能力的实现范围比论文描述更窄**

`CuratorAgent.design_algorithm` 让 LLM 返回四个任务标签之一，再直接 `get_algorithm(task)` 取固定规则；privacy controller 也是返回 task，再从代码库取固定 DP 框架和参数。当前成功验证的是有限任务集合上的识别、规则执行和聚合。它没有评估 LLM 如何生成或调整 send/update/aggregate，也未验证新增任务、未知任务或不同表述下的算法建立能力。论文同样依赖知识库，因此不应把它夸大为“从零发明算法”；但当前 `task_acc=1` 也不足以证明完整的算法设计能力。

选任务解析失败时 curator/controller 会用 `infer_task_from_prompt` 回退；两者标签不一致时 `framework.py:143` 只警告而继续执行。这会影响更复杂输入时的评估有效性，并可能让执行算法与噪声校准不匹配。应分别记录原始识别准确率、回退后的执行结果，并在参数与算法不一致时终止该次运行或明确标为无效。

**6. 当前评估和实验可追溯性的缺口**

第一，当前 delta 与论文 Table 6 不同。当前 `experiments.py:256` 计算 `abs(mean(RE_LLM) - mean(RE_same_noise_rule))`，论文表格则与其 GT 统计结果比较。当前同噪声对照更适合定位推理问题，但接近 0 不表示更接近论文，也不能直接与 Table 6 的 delta 横比。当前 delta 还可能抵消不同次误差。应保留现值，同时增加平均逐次绝对差、`mean(abs(estimate_llm-estimate_rule)/denominator)`、有符号偏差、分位数与节点误差分布。

第二，当前随机源只由 `[seed, run_index]` 组成。这样可消除并发调度对 DP 随机数的影响，但不同任务会共享随机模式；多个任务一起偏高不构成多份完全独立的证据。同样，GT 的矩阵 RR 消耗 n² 个随机数，agent 的逐行 RR 消耗 n(n−1)/2 个，因此相同整数 seed 也不保证 GT 与 agent 拿到同一张噪声图。应在结果中记录随机数方案版本，并区分固定噪声配对实验与独立随机重复。

第三，结果没有完整记录 seed/run_index、代码提交及未提交差异、依赖版本、数据哈希、完整脱敏配置、prompt 哈希、模型返回的实际标识、正常回复、usage 和 finish_reason。成功解析但算错的调用通常没有原始回复，故无法追查 Node 60 的根因。正式审计应在可信环境保存可回放轨迹，尤其要控制真实邻居和中间计数的访问权限。

第四，`asyncio.gather` 完成全部任务后才写 per-run 结果；中断时虽然错误日志保留，已完成的正常运行结果可能丢失。相同 tag 会覆盖已有摘要和日志。应逐次写 checkpoint，支持断点续跑并给每个实验不可覆盖的 run_id。

第五，mock 与 GT 共用 `rules.py` 和大量 DP 原语。mock 通过表明系统编排自洽，不是独立的论文正确性证明。已有统计一致性测试主要检查一个小图的 2-star，并允许均值相差 25%。论文对齐需要独立公式/已核实伪代码测试，尤其针对完整误差分布和敏感度，而非只比较共用实现的两个入口。

**7. 数值解析和运行成本仍有具体问题**

`extract_number` 把回复中的最后一个数字当答案。例如 `Unable to finish. Last processed Node 12.` 被解析为 12，而不会计入 parse_failure。`float(payload['count'])` / `float(payload['result'])` 不检查有限性，`NaN` 与 `1e309` 均可进入后续计算。send 解析只规范化类型，不核验 Sender_ID 与发送节点一致、范围有效、邻居唯一及自环。上述均为本次本地探针验证出的行为；尚无证据表明 NaN/Inf 已污染已有 pilot。

建议采用严格结果 schema、有限数检查及输出范围/身份检查。无法解析应与合法零计数分开统计。语义校验与重新请求应记录为单独实验条件，避免隐式使用规则答案修正后又报告原生 LLM 准确率。

最新 pilot 共 1785 次逻辑调用，另有 4 次重试，无最终耗尽失败。其中 3 次返回仅含 thinking 的空文本，单次已耗时约 553–801 秒，另有一次超时。PSC 每次运行耗时中位数约 686 秒（包含并发等待），单次最长约 1566 秒。重试提高完成率，但没有解决长尾延迟。`models.py` 没有记录 token usage/finish_reason，不能仅凭 thinking 块断定是输出上限或某个网关故障。

按当前调用规则，六数据集四任务各跑 10 次 PSC+Naive 约需 44700 次逻辑调用，重试另计。应先完成机制审计和轨迹记录，再扩大真实调用；当前缺少可直接计算实际 token/费用的证据。

**8. 隐私信任边界与论文假设尚未落实为部署保证**

论文第 3 页定义节点邻接数据保存在可信本地服务器，curator 不可信。当前 `NodeAgent._update` 将真实或经度裁剪的邻居列表直接写入 prompt，真实模型配置则把 node 与 curator 都交给同一 provider/端点。除非该模型服务明确位于每个节点的可信边界内，否则第三方推理服务在加噪前已经收到真实邻接信息；后续对 count 加 Laplace 并不能补回这一步保护。现有公开基准图适合功能实验，但不能据此宣称形成真实私有图上的端到端 LDP 部署。

此外，框架在中心进程构造全图，结果保存 `raw_count_sum`，诊断包含原始节点计数与规则计数。它们可作为可信离线实验材料，但应与任何对外发布的 DP 接口严格隔离。部署设计应明确各节点进程、模型服务、日志存储和 curator 的信任归属。

还有一个形式化条件：当前噪声按理想计数函数的敏感度校准，而进入 `protected_count` 的实际值来自任意 LLM 输出。仅靠“加了 Laplace”不足以证明该实际函数保持相同敏感度。需要说明模型遵循固定计数规则的假设，或者采用能约束实际释放函数的受审计计算/证明机制。一般范围裁剪可给出粗界，但不会自动恢复理想计数函数的精细敏感度。本项是隐私保证所需的实现条件，不是当前数值误差已经由隐私泄漏造成的证据。
