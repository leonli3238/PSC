**1. 灵敏度推导要点**

三角形（`psc/library.py:228`）。节点 i 的本地计数为

    c_i = 1/2 · Σ_{j ∈ N(i) ∩ N'(i)} |N(i) ∩ N'(j)|

N 是真实邻居表（受保护），N' 是投影后的噪声图 G'。G' 和 d̂max 在 ε3 阶段已公开、视为固定。翻转 i 的一个真实邻居位 j*：

- j* 进出外层求和：贡献 ≤ 1/2 · (|N'(j*)| − 1) ≤ 1/2 · (d̂max − 1)。减 1 是因为 G' 对称，i ∈ N'(j*)，但 i ∉ N(i)。
- j* 进出内层交集：涉及的 j 都在 N'(j*) \ {i} 中，贡献 ≤ 1/2 · (d̂max − 1)。

所以 Δc_i ≤ d̂max − 1。不投影时 |N'(·)| 可达 n − 1，得到 n − 2。

- d̂max − 1 依赖 `graph_projection`（`psc/dp.py:150`）的对称删边。投影若不对称，例如每个节点只裁自己的表，上界变为 d̂max − 1/2，论文写作 d̂max。两者都是合法上界，差别只影响噪声大小。
- k-star：f_D(d) = C(min(d,D),k)，紧界是 C(D−1,k−1)。论文和 Imola 2021 写的是 C(D,k−1)，同样合法但偏松。`floor_tight`（默认）用紧界，`legacy` 用论文写法。
- 小问题：`psc/library.py:262` 给 LLM 看的 `sensitivity_text` 仍写 `C(d_max, 1) = d_max`。实际 GS 来自机制配置，默认 `floor_tight` 下文字说明与实际取值相差 1。

**2. GT-PSC 与论文的对齐情况**

论文口径：GT 每格跑 1000 次；Naive 和 PSC（LLM）每格只跑 10 次（`paper/psc_acl2026.txt:626-641`）。因此 GT 行可以精确比较；LLM 行的 10 次均值噪声很大，见第 3 节。

当前 `floor_tight` 的 1000 次 GT（`results/ground_truth/gt_all_r1000_floor_tight_20260930/table.md`）：

- degree、triangle、全部 GT-Naive 与论文一致；
- 2-star、3-star 的 GT-PSC-B 大体一致；
- 3-star GT-PSC 六图平均 0.3756，论文 0.3649；
- 2-star GT-PSC 六图平均 0.1039，论文 0.0647，**六格全部偏高**。

**2.1 逐格显著性（`kstar_se.py`）**

z = (论文 − 本地期望) / 1000 次均值的标准误。

| 数据集 | 2-star 本地 | 论文 | z | 3-star 本地 | 论文 | z |
|---|---:|---:|---:|---:|---:|---:|
| CU | 0.1503 | 0.1062 | −11.3 | 0.6955 | 0.8035 | +5.2 |
| Do | 0.0930 | 0.0585 | −14.6 | 0.3402 | 0.3434 | +0.3 |
| ML | 0.0803 | 0.0444 | −18.7 | 0.2520 | 0.2077 | −7.3 |
| CS | 0.2023 | 0.1210 | −15.8 | 0.6649 | 0.5410 | −6.6 |
| EE | 0.0475 | 0.0295 | −15.8 | 0.1778 | 0.1647 | −3.0 |
| PM | 0.0450 | 0.0284 | −15.5 | 0.1248 | 0.1290 | +1.4 |

- 3-star 只是"平均接近"：逐格看，6 格里有 4 格显著不同，正负方向都有，平均时相互抵消。3-star 的 GS 随 D 平方增长，floor/ceil、±1 这些选择就能让误差变动 10–25%，所以它对机制的约束较弱。`floor_tight` 本身就是对照 3-star 平均选出来的候选。
- 2-star 六格同方向偏高 11–19 个标准误，是系统性差距。

**2.2 等效噪声倍率（`kstar_consistency.py`）**

c 是使本地期望 RE 等于论文值所需的报告噪声倍率。

| | CU | Do | ML | CS | EE | PM |
|---|---:|---:|---:|---:|---:|---:|
| 2-star c | 0.707 | 0.629 | 0.486 | 0.598 | 0.592 | 0.619 |
| 3-star c | 1.202 | 1.010 | 0.802 | 0.781 | 0.921 | 1.033 |
| c2/c3 | 0.59 | 0.62 | 0.61 | 0.77 | 0.64 | 0.60 |

PM 是最干净的反例。真实最大度 237，带噪最大度均值 236.5，D 几乎没有估计误差，取整和 ±1 的影响不到 0.5%。在同一个 D、同一个 ε3 下，论文 3-star 符合 C(D−1,2)/ε3（c = 1.03），而 2-star 只需要 (D−1)/ε3 的 0.62 倍。由此可以排除所有在 2-star 和 3-star 之间共用的环节：最大度估计与取整、ε 拆分、报告结构、截断、数据与真值。

**2.3 联合可行性检验：2-star 与 3-star 是否可能来自同一套只改 k 的实现（`kstar_joint_hull.py`）**

机制族设定：

- 共用阈值 D，可取任意分布，包括 oracle 真实最大度；
- 任意 ε3 ≤ 2；
- GS 取紧界或松界；
- 本地裁剪、逐节点 Laplace、求和、最终截断。

随机 D 下，(RE3, RE2) 是固定 D 点的混合，可达集合就是这些点的凸包。条件已经比任何真实实现更有利，结果如下。"倍率"指在 3-star 等于论文值时，2-star 可达的最低 RE 与论文 2-star 之比。

| | CU | Do | ML | CS | EE | PM |
|---|---:|---:|---:|---:|---:|---:|
| 倍率 | 1.08× | 1.22× | 1.42× | 1.09× | 1.33× | 1.39× |

论文的 (2-star, 3-star) 数值对在六张图上都落在可行域外。

**2.4 其他只改 k 的候选**

- **逐节点阈值**（`kstar_pernode.py`）：D_i = min(D, ⌊y_i + m/ε2⌋)，两任务用同一个 m。2-star 降到论文水平时（m = 2–3），3-star 已降到论文的 0.13–0.65 倍。仓库已有的 GT-TriTR α=5 结果相同：2-star 0.058，3-star 0.17。`adaptive_2star` 只对 2-star 用了 margin，属于拟合，PM 0.0121 对论文 0.0284，逐格不符。
- **换总 ε**（`kstar_eps_fit.py`，ε2:ε3 = 1:4）：3-star 反推的 ε 为 1.85–2.45，围绕 2；2-star 为 2.45–3.65，且各数据集不一致。说明不是"2-star 整行用了另一个 ε"。

**2.5 不是某一行抄错（`kstar_agent_p.py`）**

在本地机制下，"10 次均值 ≤ 论文智能体 PSC 值"的概率：

- 2-star：CU 0.058、Do 0.14、ML 0.10、CS 0.002、EE 0.13；
- 3-star：0.63、0.70、0.08、0.13、0.93。

论文 1000 次 GT 和 10 次 LLM 实验两组独立结果都显示 2-star 噪声更小。

**2.6 结论**

作者实际使用的 2-star 报告尺度与 3-star 不服从同一个 C(D, k−1) 关系，论文正文没有说明这一点。不建议继续为 2-star 单独调参去拟合论文。建议把 2.2 中的 PM 论证和 2.3 的可行性检验补进 `docs/PSC_REPRODUCTION_REPORT.md` 附录 A（尚未发送），直接询问 GS 优化下 2-star 实际使用的 Laplace 尺度。

**3. 实验次数对比较口径的影响**

论文 PSC 行是 10 次均值，标准误很大。CU 三角形单次 RE 标准差约 0.87，10 次均值的标准误约 0.27–0.29，95% 范围为 [0.58, 1.67]（GT 机制 5000 次模拟）。RE 分布右偏，大多数 10 次均值会低于总体均值。

- 论文 Table 2 的 24 格中，有 9 格 PSC < GT-PSC。这在 LLM 完全正确时也是常见现象，不代表 LLM 降低了噪声。
- LLM 出错也可能碰巧降低 RE，项目中称为 lucky gain。论文 PM 三角形 PSC 0.4786 对 GT 1.0863，可能属于这种情况：同一张图的 degree 为 0.0666 对 0.0030，说明 LLM 在 PM 上错得多。这一点只是推测。
- 论文称"degree / 2-star 上 PSC 与 GT 的偏差更小，因为更容易计算"，但这里的偏差混有 10 次抽样噪声，论文没有分离两者。

建议的比较口径：

1. 机制层：本地 1000 次 GT 对论文 1000 次 GT。
2. LLM 执行层：用同噪声回算的差值（`delta`、`exec_exact`），不与论文 10 次的数值比较。
3. 本地 10 次 PSC 与论文 10 次 PSC 之间无法精确比较。

**4. CU 实验日志分析（gpt-4.1-mini 节点 + gpt-4.1 curator）**

对象：`results/exp1/gpt41mini-node_gpt41-curator_exp1_CU_triangle_r10_PSC/` 与 `..._CU_3-star_r10_PSC/`，分别有 1010 和 500 次 LLM 调用。

**4.1 误差分解（同噪声）**

| 任务 | PSC RE | 规则回算 RE | LLM 差值 | 节点 update 错误 | 聚合错误 |
|---|---:|---:|---:|---:|---:|

| 3-star | 1.0233 | 1.0229 | 0.0004 ± 0.0004 | 0 / 490 | 1 / 10（+2.0） |

- RE 偏高几乎全部来自 DP 噪声。三角形第 1 次 RE = 3.80，单独把 10 次均值拉高约 0.28；另有 5 次截断为 0。
- 跑满 1000 次会收敛到本地 GT-PSC 的约 1.00，而不是论文 PSC 的 0.79。本地 GT 1.003 对论文 GT 0.961，差约 1.1 个标准误，一致。
- 另一组 DeepSeek-V3 节点、20 次的实验（`hy3-dsv3-1226_..._Naive-PSC_paper-directprompt`）：CU 三角形 PSC 0.9952，GT 1.0028，同样印证上述结论。

**4.2 CU 三角形的 GT-PSC 约等于"恒输出 0"**

估计值恒为 0 时 RE 恒为 1.0。本地 GT 1.006，论文 0.961。表中 `rule_not_better_than_zero = 0.6`，即 10 次中有 6 次规则结果不优于输出 0。原因是 ε2 = 0.2 时 d̂max 为 16–35（真实最大度 8），每节点报告尺度约 (d̂max − 1)/0.8，远大于真值 57。

因此在这张图上，"PSC 优于 Naive"主要来自 Naive 的 LLM 计数错误，PSC 的估计本身不具备实用精度。写结论时应与 degree、k-star 这类机制优势明显的任务分开表述。

**4.3 Naive 与 PSC 的提升应拆成两部分（CU 三角形）**

| | Naive 侧 | PSC 侧 |
|---|---|---|
| 机制误差（纯代码 GT，与模型无关） | GT-Naive 1.44 | GT-PSC 1.00 |
| LLM 执行误差 | gpt-4.1 为 9.05 / 7.83，对 GT 1.44 | 约 0.001 |

- LLM 执行误差的大小取决于模型。hy3 的 CU 三角形 Naive 为 1.52，dsv3 为 1.57，接近 GT-Naive。只在会数错的模型上，差距才达到论文的 9.12 对 1.45。
- 与模型无关的提升来自机制，且因任务差别很大：degree 0.018 对 1.07，2-star 0.15 对 3.6，3-star 0.70 对 10.1，三角形只有 1.00 对 1.44。

**4.4 节点错误类型（三角形 10 个错误节点逐条核对）**

| 类型 | 例子 | 能否用规则自动检测 |

**5. DP 保证依赖的条件，以及当前实现的漏洞**

ε-边 LDP 成立需要三个条件：

- **C1**：离开节点的只有 RR 边（ε1）、带噪度数（ε2）、本地计数 + Laplace（ε3）。
- **C2**：被加噪的计数由敏感度 ≤ GS 的**固定函数**产生。
- **C3**：每个量只发布一次，重试不得重抽噪声后再次发布。

论文还隐含一个前提：节点 LLM 属于该节点的可信范围。使用远程 API 时，原始邻居表已交给模型服务商，这超出了形式化模型。这个问题与是否改进无关。

**漏洞**：`NodeAgent._update`（`psc/agents/node_agent.py:204`）直接把 LLM 解析出的数作为 `self.count`，`protected_count`（`node_agent.py:122`）直接加噪，中间没有校验。GS 是对规则函数推导的；LLM 只有在完全算对时才等于该函数，而 LLM 没有"输入改一位、输出变化 ≤ GS"的保证。因此纯 LLM 执行的 PSC（包括论文）只有在 LLM 不出错时才有形式化保证。

degree 任务的 GS = 1，最容易越界：LLM 在相邻输入上的误差只要相差 1 以上，就会超出。论文 PM degree PSC 0.0666 对 GT 0.003，说明 PM 上普遍存在度数误数，但这只表明 LLM 会数错，不等于已经越界（系统性误差在相邻输入间可能相互抵消），需要 A 方向的审计来确认。

论文 Theorem 2 的证明只有一句"由顺序组合定理"（`paper/psc_acl2026.txt:611-614`），正是隐含了上述假设。另外，论文的威胁模型假设"每个用户的连接存放在可信的本地服务器"（`paper/psc_acl2026.txt:310-311`），而实验调用的是 OpenAI API，两者本身不一致。作为论文方向的风险与复核意见，见审计方案文档第 9 节。

**6. agent 侧改进方向及其 DP 影响**

以下改进都不改动 DP 机制（RR、Laplace、投影、ε 拆分）。

**6.1 节点输出中间结果，由本地代码校验 / 计算（优先）**

- 做法：节点 LLM 以 JSON 输出各有效发送者的共同邻居列表。本地代码校验约束：发送者 ∈ 自己的邻居表；共同邻居 ∈ 两张表；共同邻居 ≠ 发送者、≠ 自己。违规则反馈并重问。计数由代码根据列表完成。
- 覆盖：4.4 中四类错误里能自动检测的三类。
- DP：全部在节点内部完成，安全。
- 改动位置：`psc/agents/node_agent.py:204` 的 `_update`，以及 `psc/rules.py`。

**6.2 节点与 curator 的工具调用（function calling）**

- 节点工具：如 `intersect`、`comb`。工具在本地运行，计算确定性的规则函数，C2 精确成立，DP 反而得到加强。
  - 风险：LLM 选错工具或参数，例如用了未投影的邻居表、k 写错，就会算出另一个函数，GS 失效。
  - 缓解：工具内部绑定 `self._update_neighbors`，LLM 只能传 `sender_id` 等引用；每个任务的计数函数固定；再加一层守卫，"LLM 值必须等于代码重算值，否则采用代码值"。这样 DP 可以严格证明，守卫的回退率可作为执行质量指标。
  - 工具返回值进入 LLM 上下文：远程模型会看到中间结果，但当前已经整表外发，不会更糟；改用只传引用的工具后暴露更少。
- curator 工具（求和、计算器）：curator 只见加噪报告，属于后处理，安全。可消除 4.1 中 +2.0 的加法错误。
- 定位说明：加守卫后，LLM 的角色从"执行计算"变为"编排与解释"。写成论文时需要明确这一点。

**6.3 发给 LLM 前由代码过滤非邻居消息**

- 在节点内完成，安全。
- 消除过滤误解类错误，三角形 update prompt 减少 44.4%。
- 改动位置：`NodeAgent.observe` 或 `_update` 构造 prompt 处。

**6.4 curator 报告不确定性（后处理，不耗预算）**

- curator 已知 GS、ε3、n，可给出报告噪声的标准差，例如三角形为 √(2n)·GS/ε3/3，据此报告置信区间。区间覆盖 0 时提示"估计与 0 不可区分"，针对 4.2 中的情况。
- 改动位置：`psc/agents/curator_agent.py:74` 的 `aggregate`。

**6.5 降低成本与延迟**

| 措施 | DP | 理由 | 收益 |
|---|---|---|---|
| send 用模板 / 代码生成 | 安全 | `_send` 的 prompt 只含 `noisy_neighbors`（`node_agent.py:177`），属于已发布数据的后处理 | 省 490 次调用，约 15 万 / 10.5 万 token（输入 18%、输出 23%） |
| 预过滤消息 | 安全 | 同 6.3 | update prompt −44.4% |
| 缓存 select / design | 安全 | 输入只有公开任务描述 | 每 10 次运行省 20 次调用，约 70 秒 |
| 压缩节点输出格式 | 安全 | 不改变发布内容 | 推理 token 预计减半 |
| 超时、重试、并发 | 有条件安全 | 噪声在 update 之后由 `collect_reports` 抽取，LLM 调用级重试不重抽噪声；整次运行重跑使用相同种子 `default_rng([seed, run-1])`，结果一致。禁止发布后用新随机数重新发布 | 524 超时一次耗时 125 秒以上；单次请求超时应低于 120 秒 |
| 公共 prompt 前缀缓存 | 安全 | 规则文本公开，放在 prompt 前部 | 降费用和首 token 延迟 |
| 多个节点合批到一个 prompt | **违反** | 节点 B 的输出会依赖节点 A 的数据，这部分敏感度未被计入 | 禁止 |
| 按私有信息选择模型（真实度数、校验失败） | **旁路泄露** | 所选模型、耗时、token 数对 curator 或服务商可见 | 只按公开信息路由，如已发布的带噪度数、来自带噪图的消息条数 |

**6.6 按难度选择模型**

便宜模型处理消息少的节点；消息多的节点，或 6.1 校验失败的节点，升级到强模型。路由依据必须遵守 6.5 中的约束。

**6.7 LLM 生成节点程序，在本地执行（扩展）**

curator 或节点 LLM 根据规则生成节点程序，在本地运行：执行误差为 0，原始数据不出节点，LLM 调用从 O(n) 降到 O(1)。仓库已有 vLLM / qwen 本地部署配置，也可以先走"节点用本地模型"的保守路线。此方向偏离论文"由 LLM agent 完成计算"的设定，适合作为扩展研究。
