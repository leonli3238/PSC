PSC k-star 差距的原因判断与解决方案（2026-09-28）

本文将已完成的诊断转化为原因判断和工程方案。当前源码、配置、数据和历史结果的哈希与研究时一致。这里描述的集成修改尚未实施；已有的内容是独立研究脚本、公式验证和离线实验。

核心判断：当前机制的绝对误差可以定位到“带噪最大度决定全体节点统一报告噪声”，三次 pilot 的波动进一步放大观感。与论文 GT-PSC 的差距尚不能唯一归因；基础源码对照与理想阈值分析已经排除“只改取整、比例就能全面对齐”的解释。解决实际误差可以通过独立估计器推进，忠实复现则需要保留机制差异和作者证据边界。

**原因一：把一个节点的最坏情况尺度应用到所有节点**

当前 2-star 直接报告 C(d_i,2)+Lap(D/epsilon3)，3-star 报告 C(d_i,3)+Lap(C(D,2)/epsilon3)，其中 d_i 先按 D 裁剪。GS 是全体节点共用的上界，而非每个节点实际计数的噪声需求。degree=2 的节点和 degree=D 的节点使用相同噪声尺度；其零均值不能消除方差。

给定 D，2-star 总报告噪声方差为 2n(D/epsilon3)^2，3-star 为 2n(C(D,2)/epsilon3)^2。因此“每节点计数很简单”和“最终估计准确”是两个不同问题。当前节点算术已经接近正确，但报告机制仍会破坏精度。

PM 真实最大度为 237，度数均方根仅约 18.93。即使 D 估计准确，最大度也远不能代表整张图的度数规模。统一最坏情况尺度在这样的不均匀图上代价尤为明显。相关代码为 `psc/library.py:224`、`psc/ground_truth.py:91`。

**原因二：小图的带噪最大度存在向上选择效应，3-star 又将其二次放大**

epsilon=2 时，估计度数使用 epsilon2=.4，即每节点度噪声尺度 2.5。对所有报告取最大值，会选择偏大的噪声项。CU 的真实最大度为 8，模拟平均 D 约为 14.86。3-star GS 从 C(8,2)=28 变成更大的 C(D,2)；当 D=19 时达到 171。

最新 CU/3-star 的具体运行中，原始计数和为真值 494，D=19，49 个独立计数报告的噪声和为 +1956.198，最后得到 2450.198。这解释了该次误差，不需要引入 LLM 算错的假设。D 偏高主要放大方差，不意味着最终估计每次都偏高。

**原因三：预算开销和裁剪增加代价，但不是全部差距**

当前最大度阶段使用 0.4，报告阶段使用 1.6。与同 GS 下直接使用 2 相比，报告噪声尺度增加 25%。这不是预算丢失，而是估计最大度的成本。减小 epsilon2 又会增大 D 的噪声，尤其影响 3-star，因此单独提高 epsilon3 并不一定改善总体效果。

真实邻居投影在部分枢纽图引入向下计数偏差，但之前的无投影诊断显示其影响不足以解释主要差距；CU 的 50000 次诊断甚至没有发生裁剪。最终非负截断对非负真值不会增大绝对误差，不应将零输出直接认定为失败。

**原因四：评估把两个不同问题叠在一起**

LLM pilot 每项只有三次，而论文 GT 每项 1000 次。CU/3-star 的 pilot 平均 RE=2.0191，本地较大样本均值约 .88，论文为 .8035。前两者的差距主要反映抽样波动。当前 k-star pilot 666 个节点 update 全部与规则一致，只有一个很小的聚合错误。

另一方面，2-star 的六图长期平均 RE 约 .114，论文约 .065，增加次数不会消除这个差距。应把“本地 LLM 相对本地代码的执行误差”和“本地机制相对论文的差距”分开报告。

**原因五：作者实际机制与公开描述之间还缺少可验证的连接**

已确认的基础算法源码采用 floor 投影、连续 GS 和不同缺省预算；复用这些细节后，2-star 仍明显偏高。进一步允许免费选择最优整数 D、给报告完整 epsilon=2、使用紧 GS，ML/EE/PM 的最优期望 RE 仍分别是 .06067/.03646/.03571，而论文是 .0444/.0295/.0284。

该结论仅限共同尺度独立 Laplace 报告的度裁剪估计器族。如果论文结果在重复实验中稳定出现，剩余解释范围是实际图或真值不同、报告公式/尺度不同、使用了其他估计器或校正、聚合/评估细节不同。论文可能存在表格或实现问题，但目前没有证据下此结论；有限样本均值也可低于期望。这一差距不能被表述为已找到唯一代码 bug。

**方案 A：保留忠实复现路径，停止无依据拟合论文数值**

1. 将当前机制、基础论文文字变体、基础源码变体分别登记，保留数据哈希、epsilon 分配、取整、GS 和截断位置。默认基线不因某个候选更接近论文而被覆盖。
2. 向作者索取 k-star GT 脚本、完整 DP/算法库、度向量、逐节点报告公式和 Table 2/3 的逐次结果。`docs/PSC_AUTHOR_INQUIRY_DRAFT.md` 已有草稿，尚未发送。
3. 取得作者材料后先对齐度向量、真值，再比较 M、D、GS、epsilon3、噪声、聚合；不能只比较最终 RE。
4. 若仍无法取得作者代码，将结果明确标为按公开描述实现，并报告未解释差距。忠实复现的验收是规格和实现有依据，不是强制贴合某个点值。

紧 GS=C(D-1,k-1) 可作为固定整数 D 下理想度裁剪函数的独立机制变体；它不自动证明任意 LLM 算错后的输出也满足同一敏感度。不能把本地私有 degree 直接用作噪声尺度而沿用原来的 DP 论证。

**方案 B：以带噪度数和组合数偏差校正降低实际误差**

推荐作为单独方法接入以下计算路径：

    可信节点代码计算真实 degree
        -> 只发布一次 y_i = d_i + Lap(1/epsilon)
        -> 代码计算校正多项式并求和
        -> 最终可选择截断为非负
        -> curator 返回数值或解释

LLM 仍可解释公开任务、选择算法或处理已发布的 y_i；确定性多项式和求和优先交给工具。若需要研究 LLM 算术表现，可增加只接收同一组 y_i 的 LLM 后处理分支，并用精确代码参考配对评估。

设 b=1/epsilon，校正公式为：

    T2_hat = sum_i [y_i(y_i-1)/2 - b^2]
    T3_hat = sum_i [y_i(y_i-1)(y_i-2)/6 - b^2(y_i-1)]

因为 E[L]=0、E[L^2]=2b^2、E[L^3]=0，截断前两式均无偏。直接使用 C(y_i,k) 会产生可计算的偏差，所以校正项不可省略。不能在节点侧先对 noisy degree 或多项式结果截断。

新方法不需要 noisy max，也不需要先花 .4 再用 1.6 报告计数。更主要的区别是其方差依赖各节点实际 degree 的矩。例如 2-star 总方差为：

    2b^2 sum_i(d_i-1/2)^2 + 5n b^4

这与当前 2n(D/epsilon3)^2 有本质区别：枢纽节点不再令所有低度节点付出同样噪声代价。3-star 的方差依赖实际度数四阶量，仍受枢纽影响，也仍有 Laplace 多项式的尾部风险。

以现有六图为例，独立研究的六图平均 RE：

| 方法 | 2-star | 3-star |
|---|---:|---:|
| 当前代码机制 | .11418 | .45134 |
| 论文 GT-PSC | .0647 | .3649 |
| 新候选 | .02189 | .03956 |

新候选相对当前代码机制的平均 RE 降低约 80.8% 和 91.2%，这些是已有固定 epsilon=2 的纯代码实验结果，不是集成后或真实模型性能承诺，也不是作者机制重建。新的估计器不属于上述受限机制族，所以更低误差不与该机制族的期望下界矛盾。

集成需要遵守明确的信息边界：真实 degree 的计算和加噪在可信节点执行；外部 LLM 只获得公开任务和已发布数据。若已经用完整 epsilon 发布 noisy degree，不再同时发布消耗额外预算的真实计数报告。多个 k-star 任务可复用同一 y_i；反复重新扰动、对外发布会累积隐私开销。这里按论文的每节点单比特 edge-LDP 口径讨论；若目标是同时保护无向边两端的完整转录，应重新按 relationship DP 分配两端预算。

**方案 C：先用可信评估决定是否采用**

1. 固定数据、公式、seed 规则和结果指标，使用独立于探索阶段的验证种子。不同机制可共享标准 Laplace 向量，但必须分别按自身 scale 变换，不能把相同实际噪声当成公平预算比较。
2. 先做六图×两任务×epsilon∈{1,2,3} 的纯代码比较，记录平均 RE、标准误、中位数、95% 分位、截断前偏差/方差和零输出率。候选已完成 epsilon=2 的研究验证；其他 epsilon 和工程集成尚待完成。
3. 将平均效应与尾部风险同时比较。不能仅因六图平均下降就接受某一数据集高分位误差恶化，也不能依据论文点值回选 seed 或参数。
4. 纯代码稳定后，在同一已发布数据上比较代码和 LLM 后处理。执行失败、解析失败、算术错误分别计数，保持公式本身的机制误差可辨识。
5. 对外报告区分 E[|estimate-truth|]/denominator 与 |E[estimate]-truth|/denominator。多次采样用于离线估计误差分布，不能把额外多次公开发布的平均当成单次 epsilon=2 的新结果。

建议优先顺序：保留当前复现基线和作者询问渠道；同时将方案 B 接入独立纯代码方法并完成方案 C；验证通过后再接入真实 agent 后处理。这样可以实际改善项目，又不会把未确认的作者机制当作已复现。
