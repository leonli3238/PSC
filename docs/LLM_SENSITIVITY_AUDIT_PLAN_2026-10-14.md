A 方向实验方案：LLM 节点的实测灵敏度与隐私审计（2026-10-14）

背景与动机见 `docs/PROJECT_AND_AGENT_IMPROVEMENT_ANALYSIS_2026-10-14.md` 第 5 节。PSC 的 ε3 阶段直接对 LLM 输出的本地计数加 Laplace 噪声（`psc/agents/node_agent.py:122`、`:204`），而 GS 是针对规则函数推导的。本实验要回答四个问题：

1. LLM 节点的实际输出是否满足"相邻输入下变化 ≤ GS"？
2. 不满足时，实际的隐私损失 ε 是多少？
3. 越界与哪些因素有关：模型、图规模、任务、消息条数？
4. agent 侧的修复（校验、工具、守卫）能否把越界消除？

本方案不修改 DP 机制，只审计和修复"执行者"。

---

**1. 研究问题与假设**

| 编号 | 假设 | 预期 |
|---|---|---|
| H1 | 纯 LLM 节点存在 Δ_LLM > GS 的相邻输入对 | CU 的 k-star / 三角形大概率为 0：GS 是 13–34，LLM 误差只有 ±0.5–2。degree（GS = 1）和大图（PM、EE）最可能越界。注意：论文 PM degree 的误差只说明 LLM 会数错，不等于越界。越界要求 x 与 x' 上的误差不同，系统性误差（例如总是少数一个）在相邻输入间会相互抵消 |
| H2 | 越界率随节点输入规模（度数、消息条数）上升，随模型能力下降 | 与 4.4 节的错误分布一致 |
| H3 | 校验 / 工具（不带回退）能显著降低越界率，但不能保证为 0 | 漏元素类错误无法被规则发现 |
| H4 | 守卫（不一致时采用代码值）使越界率为 0，且成本可控 | 由构造保证；需要测量回退率与额外开销 |

审计只能给出 ε 的**下界**：发现越界即可证伪该配置的形式化保证，但没有发现越界并不能证明满足。可证明的保证只能来自 H4 的守卫。

---

**2. 形式化定义**

记节点 i 在 ε3 阶段的输入为 x = (本地邻居表 P, 收到的消息 M, 公开参数)。公开参数包括 G'、d̂max、D、规则文本。只有 P 是私有的，其余在相邻输入间保持不变。

- 规则函数 f(x)：`psc/rules.py` 的 `update`，即 GS 推导所针对的函数。
- LLM 函数 L(x)：节点实际产生、被 `protected_count` 加噪的值。解析失败时为回退值，即 `_update` 保留的旧 `self.count`，这一点必须一并计入。
- 发布机制：M(x) = L(x) + Lap(b)，b = GS / ε3。

**2.1 相邻输入（边 LDP 下翻转一位）**

| 任务 | P 的含义 | 相邻操作 | 规则侧上界 |
|---|---|---|---|
| degree | 真实邻居表 | 加入一个非邻居 / 删除一个邻居 | Δf ≤ 1 |
| 2-star / 3-star | 投影后的表 `_update_neighbors`（\|P\| ≤ D） | 见下方耦合规则 | Δf ≤ C(D−1, k−1) |
| triangle | 真实邻居表（不投影；G' 固定） | 加入 / 删除一个顶点 | Δf ≤ d̂max − 1（推导见分析文档第 1 节） |

k-star 的耦合规则：真实表翻转一位后，按随机投影的耦合取 P'。

- \|P\| < D 时：直接加入或删除。
- \|P\| = D 时：加入操作取"不变"或"替换一个元素"两种实现，两者都是合法的投影结果；删除操作可在 P 外补入一个原先被投影丢弃的邻居。

整个机制的 DP 只需要对每个耦合对满足 |L(P) − L(P')| ≤ GS，因此替换操作也必须测。

**自检**：所有生成的相邻对都必须满足 Δf ≤ GS。这一点写成断言，用来验证相邻操作的实现是否正确。

**2.2 指标**

- 执行误差：e(x) = L(x) − f(x)，与现有 `exec_exact` 口径一致。
- 相邻变化：Δ_LLM = |L(x) − L(x')|，Δ_rule = |f(x) − f(x')|，超出量 = Δ_LLM − Δ_rule。
- 越界：确定性情形下 Δ_LLM > GS。
- 实测隐私损失：
  - L 确定时：ε_emp = ε3 · Δ_LLM / GS。
  - L 随机时：温度 0 的 API 也不完全确定，对同一输入重复 r 次得到 {y_j}、{y'_j}，输出密度为 p(z) = (1/r) Σ_j Lap(z; y_j, b)，令 ε_emp = max_z |log p(z) / p'(z)|。实现时在细网格上计算，并用尾部极限校验：

        z → +∞ 时，log 比值 → log Σ e^{y_j/b} − log Σ e^{y'_j/b}
        z → −∞ 时同理（指数取 −y/b）

    规则函数满足 ε_emp ≤ ε3，用作健全性检查。

  - **统计有效性**：用 r = 3 次重复得到的经验混合分布算出的 ε_emp 只是点估计，不是有效的下界。抽样偶然性就可能造成假越界，例如 x 得到 {5,5,5}、x' 得到 {5,5,7}。因此分两级报告：
    - **稳健越界**：x 和 x' 各自的 r 次输出完全一致，且 Δ_LLM > GS。此时可按确定性函数处理，ε_emp = ε3·Δ_LLM/GS 可以作为下界报告。
    - **疑似越界**：重复之间不一致。对这些相邻对追加采样（例如每侧 30 次），再做假设检验：选事件 S（如输出大于某阈值），Laplace 部分解析积分，L 的分布部分用 Clopper–Pearson 区间，得到 ε_lb = log(p_lower / p'_upper)。只有 ε_lb > ε3 才计为越界。这是 DP 审计文献的标准做法（Jagielski et al. 2020；Nasr et al. 2021）。
  - **解析失败或 API 失败的回退**：`_update` 在失败时保留旧值（初值 0），`chat` 在全部重试失败后返回空串。回退到常数**本身不构成越界**：如果失败概率与数据无关，x 和 x' 的输出分布中"失败分支"完全相同。应把失败当作随机事件纳入混合分布；只有当 x 与 x' 的失败概率显著不同（例如与 prompt 长度相关）时，才报告为一项隐私影响。
- 汇总（每个配置）：越界率、ε_emp 的最大值 / P95 / 中位数、ε_emp > ε3 和 > 2ε3 的比例，以及对应的总 ε 实测下界 ε1 + ε2 + ε_emp。
- 非确定性基线：同一输入重复 r 次时的不一致率和输出极差，用于区分"相邻输入导致的变化"和"API 自身的抖动"。
- 协变量：度数 \|P\|、消息条数 \|M\|、GS、d̂max、模型、数据集、任务。

**3. 相邻对的选取策略**

每个节点取 m 个相邻对。随机选取估计"平均越界率"，定向选取用于"找越界"，两者分开报告。

| 策略 | 说明 | 适用 |
|---|---|---|
| S1 随机 | 随机加入一个非邻居或删除一个邻居 | 全部任务；用于估计越界率 |
| S2 规则变化最大 | 选使 Δf 接近 GS 的翻转。三角形：加入在最多发送者列表中出现的顶点，或删除共同邻居最多的邻居。k-star：d 恰在 D 附近 | 越界最容易出现在 Δf 已接近 GS 时 |
| S3 错误诱导 | 针对 4.4 节的错误类型：加入恰为某发送者的顶点（诱发把发送者算成共同邻居）；加入一个其消息列表与自己大量重叠的非邻居（诱发过滤误解）；在长列表中加入或删除中间位置的编号 | 三角形、degree |
| S4 边界 | k-star 在 d = k−1 / k 边界和 \|P\| = D（替换操作）；degree 的长列表 | k-star、degree |

**4. 输入来源与重构**

**4.1 已有实验（不需要重跑 DP 流水线）**

从 `results/exp1/*/transcripts.jsonl` 中 phase = update 的记录取原始节点输入，从 `runs.json` 取 GS、d̂max、ε split。

- 用 `node_update_prompt`（`psc/prompts.py:191`）的固定模板解析出 node_id、邻居表、消息和 state。
- **往返校验**：用解析结果重新生成 prompt，经 `strip_structured` 处理后必须与日志中的 user 字符串完全一致。日志记录的是去掉结构化块后的 prompt，见 `psc/models.py:317`。
- 原始输入上的 L(x) 已记录在日志里，可以直接复用一次；重复采样另行调用。

**4.2 新数据集 / 新配置**

用 mock 模型（`psc/mock_model.py`，精确执行规则）和相同种子跑一次 PSC 流水线，只为生成节点输入，并保存 transcripts。DP 随机数的消耗与模型无关，因此输入与真实实验一致。

**4.3 构造相邻输入**

只改 P，M 与公开参数不变，用同一模板生成 x' 的 prompt，并用与原实验相同的 system prompt（`NODE_SYSTEM`）和解析逻辑得到 L(x')。解析逻辑包括 `extract_json`、`_state_value`、`extract_number` 回退和解析失败回退。

**5. 实验矩阵与规模**

| 阶段 | 数据 / 任务 | 节点 | 模型 | 每节点调用 | 调用总数（约） |
|---|---|---|---|---|---|
| P1 试点 | CU × {degree, 2-star, 3-star, triangle}，各取 2 个已有运行 | 全部 49 | gpt-4.1-mini | m = 4 个相邻对，x 与 x' 各重复 r = 3 次，共 (1+4)×3 = 15 | 49 × 15 × 2 × 4 ≈ 5.9k |
| P2 大图 | PM × {degree, 2-star, 3-star}；EE × 4 任务 | 按度数分层抽 60 个 | gpt-4.1-mini | 15 | 约 10k |
| P3 模型对比 | P1 全部 + P2 中 degree 与 2-star | 同上 | 本地 qwen（vLLM 已有配置）、一个更弱的模型 | 15 | 每个模型约 10k，本地运行无 API 费用 |
| P4 修复对比 | 在 P1、P2 中越界最多的 2–3 个配置上 | 同上 | 同 P1 | 每个变体 15 | 每个变体约 3k |

PM 的三角形单个 prompt 可达数万 token：ε1 = 1 时每个节点约有 120 个带噪邻居，每条消息约 120 个编号。默认不纳入，确有需要时只抽少量节点。

**P4 的执行变体**（对应分析文档第 6 节）：

| 变体 | 内容 |
|---|---|
| V0 | 纯 LLM，即现状 |
| V1 | 预过滤消息（三角形） |
| V2 | 输出中间结果 + 规则校验重问（不回退） |
| V3 | 工具调用（不回退） |
| V4 | 守卫：不一致时采用代码值（可证明满足 DP） |

**成本估计**（gpt-4.1-mini，按每百万 token 输入 $0.40、输出 $1.60 估算，以实际账单为准）：

- P1：三角形约 1.5k 次调用 × 1.4k / 0.65k token，k-star 与 degree 约 4.4k 次 × 0.3k / 0.1k token。合计约 340 万输入、140 万输出，约 $4。
- P2：主要是 PM 的长列表，估计约 1500–2500 万输入 token，约 $10–20。
- P3：本地运行，只需机时。
- P4：与 P1 同量级。

建议先做 P1 跑通流程和统计，再根据越界情况决定 P2 的抽样规模。

**7. 风险与对策**

| 风险 | 对策 |
|---|---|
| API 在温度 0 下仍不确定，单次比较会把抖动误判为越界 | 每个输入重复 r 次，用混合分布计算 ε_emp，并单独报告同输入抖动基线 |
| 只测到 ε 的下界 | 结论措辞限定为"发现越界 / 未发现越界"；可证明的保证只来自 V4 |
| 解析失败或 API 失败的回退 | 按 2.2 节作为随机事件纳入混合分布，不能按确定性 Δ 误判为越界；单独比较 x 与 x' 的失败率 |
| 重复次数少导致假越界 | 按 2.2 节分"稳健越界"和"疑似越界"两级；疑似的追加采样并做 Clopper–Pearson 检验 |
| 大图 prompt 过长、费用高 | 分层抽样节点，PM 三角形默认不做；先跑 P1 再定规模 |
| 相邻操作实现有误，导致 Δf > GS | 第 2.1 节的断言；测试覆盖每个任务 |
| 远程 API 本身看到原始数据 | 论文的威胁模型假设"每个用户的连接存放在可信的本地服务器"（`paper/psc_acl2026.txt:310-311`），而实验使用 OpenAI API，两者本身矛盾。在远程 API 下，原始数据已交给服务商，讨论 ε3 阶段的灵敏度意义有限。因此结论应以 P3 的本地模型为准（P3 应作为主实验，而不只是对照），远程模型结果作为补充 |

**判定标准**：

- 若 P1 和 P2 均未发现越界：结论为"在所测配置下 LLM 输出未越过 GS"。此时 V4 守卫仍作为可证明保证的推荐方案，但研究重点转向成本与鲁棒性。
- 若发现越界：报告最坏的 ε_emp 及其触发条件（错误类型、输入规模、模型），并以 V2–V4 的对比说明修复效果。

**9. 作为论文的关键风险（2026-10-14 复核补充）**

核心论断经复核成立：论文 Theorem 2 的证明只有一句"由顺序组合定理"（`paper/psc_acl2026.txt:611-614`），隐含假设 `Ni.count` 恰好是敏感度为 GS 的规则函数。而论文自己在 Exp1 中承认节点 LLM 会算错，并指出大图上偏差更大（`paper/psc_acl2026.txt:715-725`）。两者之间存在保证缺口。但要写成论文，需要先处理以下风险：

1. **原则本身不新。** "被加噪的量必须强制满足敏感度（裁剪 / 截断用户贡献）"是 DP 系统的基本要求；DP 审计也有成熟方法（Jagielski et al. 2020；Nasr et al. 2021；Steinke et al. 2023 单次运行审计）。新意只能来自"LLM agent 作为执行者"这一场景，以及对该场景的系统化度量与修复。投入前需要先检索文献，例如关键词 LLM agent differential privacy、DP auditing、sensitivity of LLM-generated code、verified differential privacy，确认没有已发表的同类工作。目前无法离线确认这一点。
2. **守卫会让 LLM 在 ε3 阶段变得多余。** V4"不一致时采用代码值"能证明 DP，但凡是能这样做的场景，都意味着已有代码可以直接算，LLM 计算就不必要；而真正需要 LLM 的场景（没有现成代码），守卫又无从构造。审稿人很可能抓住这一点。按影响范围拆分输入（让每次 LLM 调用只接触少数私有位，再对每项裁剪）可以在 LLM 出错时仍保证敏感度，但拆到能保证紧界时，每次调用只剩下"两个位做与运算"这样的平凡任务，同样失去 LLM 的价值。
3. **建议的强方法方向：LLM 负责设计，私有计算交给可检查敏感度的程序。** 让 curator 或节点 LLM 用一种受限的 DSL 写出本地计算，由系统自动推导并校验敏感度，可参考 Fuzz（Reed & Pierce 2010）、LightDP（Zhang & Kifer 2017）、Elastic Sensitivity（Johnson et al. 2018）等工作，再在本地执行。这样：
   - DP 由程序结构保证，与 LLM 是否算对无关；
   - LLM 的价值在于把 PSC 扩展到算法库之外的新子结构任务（论文只有 4 个固定任务，design 阶段实际上只是选择）；
   - 本审计正好作为动机实验：纯 LLM 执行存在保证缺口，并量化到具体的 ε_emp。
4. **审计可能找不到越界。** 在 CU 这类 GS 远大于 LLM 误差的配置上很可能一个也找不到。论文主线不能只押在"找到越界"上：保证缺口在形式上已经成立，审计用于量化其实际严重程度；方法部分（第 3 条）才是主要贡献。
5. **威胁模型的一致性。** 见第 7 节：论文假设本地可信服务器，却使用远程 API。新工作应明确采用节点本地模型，否则灵敏度层面的讨论会被"原始数据已外发"所掩盖。

结论：A 方向适合作为动机与度量部分。要支撑一篇完整论文，需要配合第 3 条这类"保证不依赖 LLM 正确性、又保留 LLM 作用"的方法，并以文献检索确认新意。
